# 0.1.3 FFI、POSIX、time 实现审查（2026-11-23）

- **范围**：PR #4（`feature/0.1.3-ffi` 相对 `master`）中的实现主体：
  `runtime/ffi-memory.c`、`runtime/ffi.c`、`runtime/{io,port,read,value,error}.c`、
  `lib/npl/ffi.sld`、`src/compiler/frontend/c-structs.npl`、
  `src/compiler/{frontend/c-functions,backend/c-stubs,driver}.npl`、
  `lib/npl/time.sld` 与 `lib/npl/time/native/time.c`、`lib/npl/unix.sld` 与
  `lib/npl/unix/native/unix.c`。
- **不在范围**：文件移动（`tests/r7rs/fixtures` → `tests/fixtures`、`stage0` →
  `bootstrap/stage0`、`tools/*.sh` → NPL 运行器）只核对了重命名相似度；
  `.agents/reviews/probes` 与正在补充的 `(npl unix)` 测试用例未审。
  syntax-case 相关提交只检查了文件规模。
- **性质**：只读审查加探针实测，未修改源码。
- **基线**：`32cfa51`；`build/bin/npli` 与 `build/bin/nplc` 由该提交构建。
  对照 Guile 3。探针与观测结果见
  [probes/2026-11-23-ffi-posix-time](probes/2026-11-23-ffi-posix-time/)。
- **编号**：本文问题为 R1 起。

## 结论

1. 内存核心本身写得仔细：对齐、边界、偏移溢出、zero-size、未知大小外部指针
   都有检查；`record` 下标校验、rest 参数错误改为可捕获错误、`read-file` 短读
   处理都正确。冻结的 `bootstrap/bootstrap.ssa` 与 `bootstrap/runtime/` 未改动。
2. 有两个**内存安全**问题（R1 目录句柄 use-after-free 段错误、R4 视图越过
   `foreign-free` 继续读写），一个**语义错误**（R2 时区偏移方向反了），一个
   **输入校验缺口**（R3 非整数参数直接当 fixnum 解码，已能改出错误的文件权限）。
3. 资源与部署层面：`make-c-struct` 从不释放（R5），`(npl time)` 每次
   `current-time` 都泄漏；`define-c-struct` 让 `(npl time)`/`(npl unix)` 的
   **每次导入**都调用 C 编译器（R6），已安装的 `npli` 没有 `cc` 就不能用这两个库。
4. 生成的 C stub 有两个回归：特性宏写在系统头之后不生效（R7），并且每个 stub
   都包含一组 POSIX 头，使与系统原型类型不同的 `define-c-function` 在
   master 上能编译、现在报 `conflicting types`（R10）。
5. 审查期间工作区已出现针对 R1-R4、R8 的未提交修复（见“修复跟踪”），
   本文证据仍以 `32cfa51` 为准。

## 问题

严重度：高 = 崩溃、内存破坏或错误结果；中 = 资源、部署或兼容性回归；
低 = 边缘路径或维护性。

### R1 目录句柄 use-after-free

`lib/npl/unix/native/unix.c` 的 `npl_unix_close_directory` 调用 `closedir` 后
未清空指针盒中的地址；之后的 `read-directory` 或第二次 `close-directory` 把已
释放的 `DIR *` 交给 libc。npli 与 nplc 都以 SIGSEGV（139）退出。
`directory-files` 不受影响（内部打开并关闭）。

### R2 时区偏移方向

`lib/npl/time.sld` 的 `time-utc->date` 在给定 `offset` 时计算
`tv_sec = second - offset` 再 `gmtime`。SRFI 19 的本地时间是 UTC 加偏移；
`date->time-utc` 也按“减去偏移”反算，所以两边一起错：
`(time-utc->date (make-time time-utc 0 0) 3600)` 得到 23 时（Guile 为 1 时），
再转回得到 -7200（应为 0）。原有测试只覆盖偏移 0。

### R3 数值参数未校验

`set-file-mode`、`create-directory`、`create-fifo`、`set-file-owner`、
`truncate-file`、`set-umask!`、`nice`、`set-file-times` 的分量直接经
`npl_fixnum_value` 解码。探针 04 中四个调用全部被接受：`(set-file-mode f 'abc)`
实际把审查用的文件改成了 `-r--r--r-T`；`(create-directory d "rwx")` 以垃圾模式
建目录。npli 上 `truncate-file` 曾因前一步改坏的权限报 `EACCES`，说明错误参数
已产生真实副作用。只有 `open-file` 在 NPL 层检查了 mode。

### R4 视图越过释放

`npl_ffi_pointer_add` 把剩余长度复制到视图里，`foreign-free` 只清空所有者盒。
释放后，所有者的 `foreign-size` 为 0，视图仍为 8，`pointer-ref-u8` 读到已释放
内存（npli 读出 12、nplc 读出 4，内容随分配器而变）。`pointer-set!` 同样会写入。
`docs/ffi.md` 只说“freed pointer has unknown size”，没有覆盖视图。

### R5 C struct 视图泄漏

`lib/npl/ffi.sld` 的 `make-c-struct` 用 `foreign-alloc` 分配，没有终结器，库内
也没有释放；`(npl time)` 的 `current-time`、`time-resolution`、`time-utc->date`、
`date->time-utc` 每次分配一到两个视图。量化（peak RSS）：10 万次
`foreign-alloc 4096` 不释放 431.8 MB、释放后 20.0 MB；100 万次 `current-time`
从 38.2 MB 增长到 56.6 MB。

### R6 导入时运行 C 编译器

`define-c-struct` 在库展开时写出、编译并运行布局探针。npli 上
`(import (npl time))` 0.72 s，`(scheme base)` 0.07 s；`NPL_CC=/usr/bin/false`
时 `(npl time)` 与 `(npl unix)` 都无法导入。核心包的 `timespec`/`tm` 布局应在
构建或安装时确定，例如生成到 `core.meta` 或包内的布局文件，并由
`define-c-struct` 优先读取缓存。

### R7 特性宏位置

`src/compiler/backend/c-stubs.npl` 输出顺序为 `#include "npl.h"`、
`<limits.h>` 等，之后才 `#define _GNU_SOURCE` / `_DARWIN_C_SOURCE`（生成文件
第 8、9 行）。系统头已被包含后再定义特性宏无效，glibc 上 `timegm`、
`tm_gmtoff` 等声明取决于偶然的包含顺序。两行必须是文件开头。

### R8 悬空声明

`runtime/npl.h` 声明 `npl_time_now_ts` 等六个函数并注明在 `clock.c`，实际只在
测试夹具 `src/compiler/tests/c-extension/time.c` 中定义。探针 09 用 nplc 编译
时链接失败（`Undefined symbols: _npl_time_now_ts`）。同一处
`npl_time_timegm_prim` 之后残留了原属 `npl_current_second` 的
`/* absolute path or #f */` 注释。

### R9 方括号不配对

`runtime/read.c` 与 NPL 词法器把 `[`/`]` 当作 `(`/`)` 的别名，但不检查配对：
`(1 2]`、`[a b)` 都读成列表，Guile 与 Racket 均报读错误。多余的 `]` 也报
“unexpected )”。若方括号是为 syntax-case 写法加入，应记录配对规则并加读错误
用例。

### R10 stub 头文件冲突

stub 现在固定包含 `<time.h>`、`<sys/stat.h>`、`<dirent.h>`、`<pwd.h>`、
`<grp.h>`、`<sys/utsname.h>`、`<sys/resource.h>`，随后输出按 NPL 类型生成的原型。
对 libc 函数的 `define-c-function`，只要 NPL 类型与系统原型不完全一致就编译失败。
探针 11 `(define-c-function c-time "time" (pointer) -> long)` 报
`conflicting types for 'time'`；master 的 stub 只含 `npl.h` 与标准头，同一声明可用。
建议只为实际用到的 `struct:` 类型输出头（由 `define-c-struct` 记录所需头），
或让 `define-c-struct` 显式声明头文件。

### R11 C 层小缺陷

- `npl_unix_nice` 调用前未清零 `errno`，合法返回 -1 时可能误报错。
- `npl_unix_create_temp_file` 在 `mkstemp` 失败路径泄漏 `template`。
- `npl_unix_glob` 对 `GLOB_NOSPACE`/`GLOB_ABORTED` 使用 `errno`，glob 不保证设置。
- `npl_port_from_fd` 在 `fdopen` 失败时不关闭描述符，`open-file` 泄漏 fd。
- `npl_unix_posix_error_name`/`_message` 在类型检查前先 `npl_header(value)`；
  目前只是计算地址不解引用，但顺序应调换。

### R12 文件规模

`src/compiler/frontend/syntax.npl` 由 774 行增长到 1074 行，超过 AGENTS.md 的
800 行软上限且 PR 未说明。syntax-case 已有 `syntax-eval*.npl`、
`syntax-primitives.npl`，新增的过程宏部分可移入。

## 建议的测试用例

原则：每个修复至少有一个 `src/compiler/tests/` 单元用例；行为在 npli 与 nplc 都可
观察的，放入 `tests/fixtures/` 差分夹具。名称中的 “raises” 指用 `guard`
捕获并断言错误对象（谓词、消息前缀或 `posix-error-name`）。

### A. 外部内存与视图（`src/compiler/tests/ffi-memory.npl`）

1. 释放后通过所有者读/写：`pointer-ref`、`pointer-set!` 报错。
2. 释放后通过视图读/写报错（R4）；视图的视图同样报错。
3. 释放后 `foreign-copy` 所有者或视图报错。
4. 重复 `foreign-free` 同一所有者：定义并测试行为（无操作或报错）。
5. `foreign-free` 视图、`null-pointer`、外部（未知大小）指针分别的行为。
6. `pointer+offset` 偏移恰为 size（得到 0 长度视图，访问报错）、size+1 报错、
   视图上再偏移累加 `pointer-offset`。
7. 每种类型的边界值：`u8` 255/256、`i8` -128/-129、`u64` 2^64-1/2^64、
   `i64` 最小/最大、负数写入无符号类型报错、非整数写入整数类型报错。
8. `float` 写入超范围 double、NaN、±inf 的往返。
9. 对齐参数：0、3、2^20、2^20+1、非整数报错；小于指针宽度时向上取整。
10. `foreign-alloc` 负数、非整数、超大尺寸（`posix_memalign` 失败）报错而非崩溃。
11. `pointer-ref-pointer` 读出的指针大小未知；对其 `pointer+offset` 不检查上界。
12. `c-array`：负长度、长度与类型宽度乘积超出视图、`vector->c-array` 写入既有
    指针时越界、元素类型不匹配报错。
13. 压力：循环 10^5 次 alloc/free 与 `with-resource`，GC 期间指针盒存活正确
    （配合 `NPL_GC_VERIFY`）。

### B. C struct 与 stub（`c-structs.npl`、`c-extension/`）

1. `make-c-struct` 后释放：提供 `free-c-struct` 或以 `with-resource` 释放，
   释放后 `c-struct-ref` 报错（R5）。
2. 每种字段类型（含 `bool`、`size_t`、`pointer`、`float`）读写往返；
   未知字段、非 view 参数报错。
3. `struct:name` 参数传入错误类型的 view、普通记录、长度不足的记录报错
   （覆盖 `npl_ffi_struct_pointer`）。
4. 生成的 stub：特性宏位于首行（R7）；只包含声明所需的头（R10）；
   对 libc 函数用 `pointer` 声明 `time` 能编译（R10 回归）。
5. 未知 C 类型、未知字段名、探针编译失败的诊断文本（编译期 fatal 夹具）。
6. 布局缓存：同一 struct 在一个编译单元中只探测一次；安装后的核心包导入不调用
   `cc`（`NPL_CC=/usr/bin/false` 导入 `(npl time)` 成功，R6）。
7. 交叉检查：`c-struct-size` 与 `sizeof`、字段偏移与 `offsetof` 在 C 夹具中一致。

### C. SRFI 19（`srfi-19.npl` 与 `tests/fixtures/time`）

1. 偏移 +3600、-3600、+19800（+05:30）、-43200、+50400：`time-utc->date`
   各字段与 Guile 一致，`date->time-utc` 往返等于原秒数（R2）。
2. `date->string` 的 `~z` 对正、负、半小时偏移的格式。
3. `string->date` 解析 `+0530`、`-0800` 后转回 UTC。
4. 纳秒保留：`make-time` 带 999999999 纳秒经 date 往返不丢失。
5. 闰年与边界：1900-02-28/03-01、2000-02-29、2038-01-19 03:14:08 之后、
   1969-12-31 23:59:59（负秒）。
6. `add-duration`/`subtract-duration` 的纳秒进位与借位、负 duration。
7. `time-difference` 类型不匹配报错；`time-monotonic` 与 `time-utc` 混用报错。
8. 本地时区路径：设 `TZ=UTC`、`TZ=Asia/Shanghai`、`TZ=America/New_York`
   （DST 边界日）分别运行，`date-zone-offset` 与 `date-dst?` 正确。
9. `date-week-number`、`date-year-day` 在 1 月 1 日为周日/周一的年份。
10. 资源：循环 10^6 次 `current-time` 与 `time-utc->date`，peak RSS 不随次数
    线性增长（R5 回归，可用探针 06 的 `time` 模式）。

### D. SRFI 170 / `(npl unix)`（`srfi-170.npl` 与 `tests/fixtures/unix`）

1. 目录句柄：关闭后 `read-directory`、重复 `close-directory` 报错而非崩溃；
   `read-directory` 读到 eof 后再读仍为 eof；dotfiles 参数为 `#t`/`#f`（R1）。
2. 所有数值参数传入符号、字符串、浮点、负数、超出 `mode_t`/`uid_t`/`off_t`
   范围的值，均为可捕获错误（R3）；对 `set-file-times` 的秒与纳秒分量同样检查。
3. 错误对象：`ENOENT`、`EEXIST`、`ENOTDIR`、`ENOTEMPTY`、`EACCES`（非 root）
   下 `posix-error?`、`posix-error-name`、`posix-error-message`、
   `error-object-irritants`；非 posix 错误上 `posix-error?` 为 `#f`。
4. `file-info` 对文件、目录、符号链接（follow 为 `#t`/`#f`）、FIFO、端口；
   `file-info:atime` 等为 `time-utc` 且纳秒在范围内。
5. `set-file-times`：`time/now`、`time/unchanged`、显式时间往返，
   只给一个时间报错。
6. `open-file`：每种端口类型、每个 flag 组合（`open/exclusive` 对已存在文件得到
   `EEXIST`、`open/truncate`、`open/append` 追加）、mode 生效（受 umask 影响）、
   非法端口类型报错且不泄漏 fd。
7. `fd->port` 与 `port-fileno` 往返；关闭端口后 fd 失效；非文件端口
   `port-fileno` 为 `#f`，`terminal?` 为 `#f`。
8. `create-temp-file`：前缀所在目录不存在时报错；两次调用名称不同；
   `call-with-temporary-filename` 在 maker 返回 `#f` 时重试，超过次数报错。
9. `umask`/`set-umask!` 往返且恢复；`set-current-directory!` 后相对路径解析，
   测试结束恢复工作目录。
10. `user-info`/`group-info`：按 uid 与按名查找一致；不存在的名字返回 `#f`；
    `parsed-full-name` 处理 `&` 与逗号分段。
11. 环境变量：设置、覆盖、删除、删除不存在的名字；名字含 `=` 报 `EINVAL`。
12. `glob`：无匹配为空表；带空格与特殊字符的文件名；结果有序。
13. `nice`：参数为 0 时返回当前优先级且不报错（R11）。
14. 资源：循环 10^4 次 `open-file` 失败路径与 `open-directory`/`close-directory`，
    进程打开的 fd 数不增长（R11）。

### E. 读取器与运行时

1. 方括号：`[a b]` 读为列表；`(a b]`、`[a b)`、`]`、`[a . b)` 均为读错误
   （R9），npli 的 `read`、nplc 编译源码、REPL 三条路径同一夹具。
2. 反斜杠标识符：`\x`、`a\b` 报错，`|a\b|` 合法；npli 与 nplc 一致。
3. `record` 下标：0、length、负数、非 fixnum 报错（已有部分，补负数与非 fixnum）。
4. `read-file` 对目录、无权限文件、读取期间被截断的文件（短读）报错。
5. `run-process*`：stdin/stdout/stderr 重定向组合；程序不存在得到 127；
   被信号终止得到 128+N；参数非字符串报错且不泄漏已分配的 argv。

### F. 驱动与安装

1. 安装前缀布局：`core.meta` 位于运行时旁与 `lib/npl/native` 两种布局都能找到；
   缺失时导入核心包给出明确错误而非链接器报错。
2. 只导入 `(scheme base)` 的程序不链接任何核心包归档（或链接后不增大二进制，
   视设计而定），并测量编译时间不受影响。
3. 外部包（crc32、zlib）在 npli `-l` 与 nplc 链接两种模式下行为一致。

## 修复跟踪

审查期间工作区出现以下未提交改动，以 `20:27` 构建的 npli/nplc 复跑：

| 编号 | 工作区改动 | 复跑结果 | 剩余 |
|---|---|---|---|
| R1 | 目录句柄登记表，关闭后报 `directory is closed` | 01 报可捕获错误 | 句柄表为全局链表，线程化（T1）时需加锁 |
| R2 | 改为 `+ offset`，加正偏移用例 | 未复跑 | 补负偏移与半小时偏移 |
| R3 | `require-integer`/`require-nonnegative` 包装 | 未复跑 | 范围上界（`mode_t` 等）仍未检查 |
| R4 | 全局活跃分配链表，访问时检查 | 05 报 `allocation was freed` | 每次访问线性查找，分配多时 O(n)；地址复用后旧视图会被误判为存活 |
| R8 | 删除 `npl_time_now_ts`/`_resolution_ts` 声明 | — | 其余四个 `npl_time_*_ts` 仍悬空 |

R4 的修复建议改为把“块”提升为独立的共享状态：所有者与视图都引用同一个小
控制块（`{base, size, live}`），释放时置 `live = 0`。这样检查为 O(1)，地址复用
也不会让旧视图复活；控制块本身可以是 GC 对象，由指针盒引用。
