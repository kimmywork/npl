# 2026-11-16

## 0.1.3 M0a: syntax-rules conformance

- Fixed macro-expanded single `define` joining body/top-level scope.
- Fixed depth-0 pattern variables in ellipsis templates.
- Added two-pass body syntax installation so later internal macros are visible
  in earlier lambda bodies without allowing them in earlier initializers.
- Added definition-time template ellipsis depth validation.
- Rejected same-level multiple ellipses in patterns.
- Renamed template-introduced top-level definitions per expansion so nplc and
  npli agree with Guile's hygiene behavior.
- Unified bare backslash rejection across nplc/npli readers.
- Added `macro-conformance`, macro/reader negative contracts, and a new
  hyphenated library hygiene case.
- Relayed the seed (`be5c7ba7...`); full compiler gate passes 58 suites and
  81 negative checks.

## 0.1.3 M0b: SRFI 46 and SRFI 149

- SRFI 46: verified list/vector tail patterns, custom ellipsis identifiers,
  and custom-ellipsis tails; added `srfi-46` feature and suite.
- SRFI 149: implemented adjacent template ellipses and deeper template
  repeats (flattening/lifting), with definition-time depth validation;
  added `srfi-149` / `srfi-149-compatible` features and suite.
- `(srfi 149)` is a feature-detection library; `syntax-rules` remains core
  syntax until the M6 core-syntax export work.

## M3 hygiene and M6 core-syntax exports

- Added per-transcription source marks; alias lookup now uses the template
  identifier's definition mark instead of any mark, fixing the nested
  `let-syntax` capture probe while preserving macro-introduced bindings.
- Core syntax names are exported by `(scheme base)` and take part in
  `only`/`except`/`rename`/`prefix`; `(srfi 149)` now exports the same
  `syntax-rules` binding.
- Added `macro-core-syntax` and expanded `macro-conformance`.

## Declarative syntax-case subset

- Added `syntax-case` transformer specifications of the form
  `(lambda (stx) (syntax-case stx (literal ...) [pattern (syntax template)] ...))`
  and lowered them to the existing syntax-rules matcher and template engine.
- Added `[...]`/`[]` reader support in nplc and npli.
- Added `syntax-case` suite (4).
