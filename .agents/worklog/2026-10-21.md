## 2026-10-21 10:30 CST — R0 runtime argument errors raise error objects

- Audit of the 73 `exit(1)` sites in runtime/: argument and OS errors a
  program can cause became catchable error objects; internal invariant
  failures stay fatal (documented in runtime/error.c).
- Converted:
  - `runtime/numeric.c`: `numeric_error` (9 sites: exact-integer
    expected, division by zero, zero denominator, unordered complex
    comparison, exact/inexact conversions, invalid decimal integer) now
    calls `npl_primitive_error` with the offending argument (the dividend
    for division by zero, as `(scheme base)` reports).
  - complex.c `make-rectangular`, inexact.c `inexact-bits`; control.c
    `value context: expected 1 value` (irritant: the value count),
    `call-with-values` consumer, parameter checks (`not a parameter`,
    converter, parameter arity), `make-promise`/`delay` thunk,
    `with-exception-handler` handler, `dynamic-wind` before/after.
  - io.c `read-file` size failure and `run-process` output setup as file
    errors, `run-process` wait failure; port.c stream write failure as a
    file error; read.c a syntax error outside `read-result` (the raw `read`
    primitive) as a read error object (new `npl_primitive_read_error`).
- Kept fatal: compiler-emitted calls with impossible arguments (type
  guards, environment index, tail-request arity, operation codes, internal
  arity), corrupted runtime frames (wind, handler, parameterize binding
  chains, promise and raise callbacks), escape-only continuation limits
  (not used by the full compiler), UINT32_MAX length limits, and the final
  report of an uncaught raise.
- Found and fixed while testing: four sites tested the tagged-boolean
  `npl_number_p` with `!`, which is never true, so `exact->inexact`,
  `inexact->exact`, `make-rectangular`, and `zero?` on a non-number
  accepted it (`exact->inexact 'a` reached `numerator`; `make-rectangular`
  returned). `npl_number_zero_p` returned the right answer by accident.
- Tests: new native suite `src/compiler/tests/runtime-errors.npl` (14
  checks through `(prefix (npl primitive) p:)` and control operators, each
  caught by `guard` with who, message, and irritant; the process survives).
  `check_full_compiler.sh` registers it and its value-context contracts now
  expect `value context: expected 1 value: N`; `check_numeric_reference.sh`
  expects the uncaught report `who: message: 1`. Native only: npli
  implements the raw names itself and still exits on `(p:npl_number_quotient
