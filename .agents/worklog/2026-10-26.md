## 2026-10-26 CST — nplc runs the program's top level in order (R7RS 5.1)

Requested by the user: nplc no longer depends on a `main` procedure; it
compiles the top-level forms in order like npli and generates the C main.
Decided with the user: `main` is an ordinary name (R7RS), done before P6.

- `src/compiler/frontend/control-program.npl` (new, split from
  control.npl, 799 -> 663 lines): procedure definitions become top-level
  functions and constant variable definitions static data; runtime
  variable initializers (as assignments) and expressions run in source
  order in one procedure `_npl_program`; the generated entry `_npl_entry`
  calls it with a continuation returning 0 and is emitted as the C main.
  A program that reaches its end exits 0; `(exit n)` ends it earlier.
  Removed: CONTROL-MAIN-SOURCE/-TARGET renaming of `main`, the "program
  needs main" and "top level must be definitions" errors.
- `backend/state.npl` `function-symbol`: top-level procedures are emitted
  as `_npl_fn_<sanitized>`, so program names cannot collide with C symbols
  (`main`, libc `free`/`read`). sanitize escapes `_`, so no user name maps
  into `_npl_`.
- `src/compiler/driver.npl` ends with a top-level `(exit (driver-run ...))`.
- Seed transition, two steps: the old seed only runs `main`, so a
  transitional driver kept both a `main` and a top-level call; the edited
  source built gen2 (gen2 == gen3 by hand), installed as seed; then the
  final driver and a strict relay.
- Migration (100 files, +149/-263): examples and all 33 R7RS fixtures put
  their code at top level (driver-hello, c-extension, load, exit-status,
  script test); test suites, runtime-error contracts, npli's
  src/repl/main.npl and the evaluator test programs keep `(define (main))`
  and end with `(main)`. check_repl.sh, tools/bench.py, and
  tests/chibi/native_adapt.py no longer append or generate `(main)`.
  Compile-error contracts (reader, macro, library, c-primitive) unchanged:
  they fail before running. stage0 `nplc0` programs unchanged (frozen).
- docs/toolchain.md states the rule; docs/ffi.md drops the npli `(main)`
  note.

## 2026-10-26 CST — P6a C pointer type, (npl ffi), installed npl.h

Decided with the user (2026-10-24/25): a new box type without finalizer;
release is explicit, through the C library's own function, made
deterministic by `with-resource`.

- `runtime/npl.h`: `BOX_POINTER` 24, `NplPointer` (header + `void *`);
  `npl_pointer`, `npl_is_pointer`, `npl_pointer_address(value, who)`
  ("who: expected a pointer"), and the procedures below. The collector
  treats it as a leaf (no children; default visitor case).
- `runtime/ffi.c`: constructors and `pointer?`, `pointer-null?`,
  `null-pointer`, `pointer->integer` (exact integer through
  `npl_integer_from_string`, so addresses above the fixnum range work).
- `runtime/numeric.c` `npl_eqv`: two pointer boxes are eqv? when their
  addresses are; `equal?` follows through eqv?.
- `runtime/write.c`: `#<pointer 0x...>` with `%llx`, not `%p` (glibc
  prints a null `%p` as "(nil)").
- `primitive-table.npl`: four rows; `lib/npl/ffi.sld` (new) exports them
  and `with-resource` (dynamic-wind, an `open` flag so release runs once).
- `npl.h` installed as `PREFIX/include/npl/npl.h`, mirrored in the build
  tree (`build/include/npl/npl.h` link); `tools/check_install.sh` compiles
  clamp.c against the installed header.
- Tests: `src/compiler/tests/c-extension/pointers.{c,npl,out}`: a counted
  malloc resource; predicates, eqv?/equal?, write, type error, and
  with-resource release on normal return, caught raise, escape, re-entry
  (released once, `(reentered 2 0)`), and exit. Run by
  check_full_compiler.sh (nplc, `-Wall -Wextra -Werror`) and check_repl.sh
  (`npli -l` shared library). A first version looped forever: the
  re-entry counter was incremented before the captured continuation, so
  each resume saw entries = 1 again; it now increments after it.
- docs/ffi.md "Pointers And Release", header path; docs/toolchain.md
  install layout.

## 2026-10-26 CST — P6b prerequisite: values result type for C primitives

Checked first, as planned: a C function returning `npl_make_values` works
with call-with-values and let-values under both nplc and npli. Found a
semantic difference where one value is required: nplc treated a C
primitive call as a synchronous operand, so `(+ 1 (divmod 7 2))` raised
"+: expected a number" and `(list (divmod 7 2))` stored a
#<multiple-values> object silently, while npli raised "value context:
expected 1 value". Builtin rows never return several values, so only user
C functions were affected.

- `c-primitives.npl`: result type `values` (result only). A registered
  symbol is reused only if it agrees on `values` as well as the operand
  count; otherwise "C primitive declaration conflicts with registered S".
- `primitive-table.npl` `primitive-row-multiple-values?`.
- `control.npl`: a call of such a row is not simple, so it reaches a
  continuation, which applies `npl_expect_one` where one value is
  required. Other rows are still called in place (no added cost).
- Tests: `src/compiler/tests/c-extension/values.{c,npl,out}` (receivers,
  tail position, apply, operand and list-element errors, argument error),
  run by check_full_compiler.sh (nplc) and check_repl.sh (npli -l); new
  contract `c-primitive-values-conflict`.
- docs/ffi.md: the `values` result type; conflict diagnostic updated.
