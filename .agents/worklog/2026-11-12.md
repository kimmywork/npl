## 0.1.1 release hardening (branch `release/0.1.1`)

Started from the read-only review recorded in
[2026-11-12-0.1.0-state-review](../reviews/2026-11-12-0.1.0-state-review.md).
The branch fixes the release blockers and the two most visible diagnostic
defects; it does not change language semantics.

- Release files: MIT `LICENSE`; root `README.md` and a GitHub Pages
  `docs/README.md`; Linux-only GitHub Actions gate
  (`.github/workflows/ci.yml`, `ubuntu-24.04`, no relay).
- Version: `VERSION` and `project(npl VERSION ...)` are 0.1.1;
  `src/compiler/common/version.npl` is the single source constant for
  `nplc --version` and `npli --version`. `check_driver.sh` checks the three
  values, and `check_install.sh` checks the installed binaries.
- Gate locale: `tools/utf8_locale.sh` selects `C.UTF-8` on Linux and
  `en_US.UTF-8` on macOS (override `NPL_TEST_LC_ALL`); `run_tests.sh`,
  `run_r7rs_fixture.sh`, and `run_chibi_suite.sh` source it. The 0.1.0
  review failed `unicode-strings` and `unicode-char` only because Guile
  escaped non-ASCII output under `LANG=""`.
- Compiler diagnostics: `fatal`, `fatal2n`, the reader paren/byte errors,
  and the backend datum/unknown-call errors write to standard error with the
  `nplc:` prefix. `driver-emit-ssa` no longer relays the partial SSA file;
  an arity error after SSA emission is now 69 bytes on stderr instead of

- Features: `features` advertises `full-unicode`, `ratios`,
  `exact-closed`, `exact-complex`, `ieee-float`, `posix`, and `unix`;
  `cond-expand` accepts the same identifiers and treats an installed
  `(srfi ...)` or user library as available when its `.sld` file exists, not
  only after it is loaded. The `libraries` suite grows from 16 to 20 tests
  (including a new `conditional-only` library).
- Docs: `docs/testing.md` now reports 56/57 stages and 30/77 compiler
  checks, `docs/toolchain.md` reports the 11.1 G self-compilation figure and
  the new `--version`/stderr contract, `docs/extending.md` and
  `docs/r7rs-conformance.md` describe the feature list and library

## 0.1.2: canonical hash tables and internal namespace

  `lib/npl/hashtable.scm`; `(npl hashtable)` is now canonical and

## 0.1.2 I2 and partial I3

Branch `feature/srfi-i2-i3`, after 0.1.2 was merged to master.

I2 (strings):
- `(npl string)` / `(srfi 13)`: compact SRFI 13 implementation over a shared
  `lib/npl/string/kernel.scm` (ranges, criteria, counts). Character-set
  criteria are not supported (no SRFI 14); criteria are chars or predicates.
  `string-map` and `string-for-each` re-export `(scheme base)` so
  `(scheme base)` + `(npl string)` import cleanly, which gives up their
  optional range arguments.
- `(npl string cursor)` / `(srfi 130)`: opaque cursor records; all start/end
  arguments accept cursors or indexes; adds `string-contains-right`,
  `string-replicate`, `string-split`, and `string-remove`.
- `(npl string immutable)` / `(srfi 140)`: istrings are frozen NPL strings
  (`npl_freeze_literal`); `istring?` probes with an empty `string-fill!`.
  Includes UTF-8/UTF-16 conversion in NPL.

I3 (started):
- `(npl vector)` / `(srfi 133)`: complete surface; `vector-copy` accepts a
  fill value, so it is defined rather than re-exported.
- `(npl data stream)` / `(srfi 41)`: delay-based streams, including
  `stream-unfolds` and a simplified `stream-match`/`stream-of`.
- `(npl data generator)` / `(srfi 158)`: full generator and accumulator
  surface; coroutine generators use call/cc.
- `(npl data unifiable-box)` / `(srfi 161)`: disjoint-set forest with path
  compression.
- `(npl data multiple-value-box)` / `(srfi 195)`: shares
  `box`/`unbox`/`set-box!` with `(npl data box)`, which now stores a value
  list so the two SRFIs use identical bindings.

## 0.1.2 SRFI 47 arrays and reader literals

Completed SRFI 47 in the same branch instead of a separate increment.

- `(npl data array)` / `(srfi 47)`: `array?`, `make-array`,
  `make-shared-array`, `array-rank`, `array-dimensions`,
  `array-in-bounds?`, `array-ref`, `array-set!`, and the uniform-array
  prototypes (`ac64` ... `at1`). Rank-1 arrays are vectors and strings;
  nested vectors are rectangular arrays; shared, rank-0, and prototype
  values use an array record. Prototypes store a fill value rather than a
  distinct byte-array representation.
- `#nA(...)` array literals now work in both readers:
  - `src/compiler/reader/lexer.npl` recognizes `#<digits>A`; `datum.npl`
    builds nested vector datums.
  - `runtime/read.c` does the same for `(scheme read)`, `load`, and the
    `npli` REPL, and still distinguishes datum labels `#n=` / `#n#`.
- Literal arrays read as nested vectors and are immutable constants; use
  `make-array` for mutable arrays.
- `srfi-47` suite: 21 tests, including the compiled reader, the C reader,
  datum labels, shared arrays, and prototypes.
- Seed relayed: `bootstrap/current.ssa` is 263,946 lines with SHA-256
  `a159900b60131c63cb2b432ac4b0679cacd6515ac95c18f2dbe61c05c3713e4e`.
