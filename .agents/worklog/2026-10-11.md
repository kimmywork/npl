# Worklog 2026-10-11

## 2026-10-11 15:20 CST — L6a+b Unicode strings and characters

- `runtime/string.c` owns the string layout: narrow (8-bit, Latin-1) or
  wide (32-bit) characters, O(1) indexing; storing a character above 255
  into a narrow mutable string moves the characters to an out-of-line
  `BOX_STRING_DATA` buffer (`NPL_FLAG_WIDE | NPL_FLAG_OUT_OF_LINE`) so the
  string keeps its identity. UTF-8 encode/decode (U+FFFD for invalid
  input), width-independent hashing and comparison (symbol interning).
- Characters are Unicode scalar values (`integer->char`, lexer `\x`
  escapes and `#\x` names). The compiler emits wide static strings and
  symbols when a character is above 255.
- Ports: textual memory ports keep UTF-8 in bytevector buffers; stream
  ports have an 8-byte pushback, so `peek-char`, the reader's lookahead,
  and `char-ready?` lose no bytes. `char-ready?` is character-based (a
  partial UTF-8 sequence is not ready; Decision 3); `u8-ready?` is the
  byte query (`npl_byte_ready_p`).
- `write`: R7RS character names (U+0000 as `#\nul`, like Guile and
  Racket), hex escapes for Guile's non-graphic set (categories Cc Cf Cs Co
  Cn Zs Zl Zp except SPACE), from `runtime/unicode_tables.h` generated by
  `tools/gen_unicode.py` (unicodedata 15.1.0). `read` accepts `\x..;`,
  `\a`, `\b`, `#\x..`, and all R7RS character names.
- New primitives `npl_string_to_utf8`, `npl_utf8_to_string` (raises on
  invalid UTF-8, like Guile), `npl_byte_ready_p`. C boundaries (paths,
  environment, process arguments, `read-file`) transcode UTF-8.
- `runtime/io.c` (1,667 lines) split into `port.c` (784), `write.c`,
  `read.c`, and `io.c` (process and host services) with a private
  `port.h`. Unused `npl_lex_tokens` removed.
- Shared fixture `unicode-strings`; `primitive-errors` integer->char case
  now uses a surrogate.
