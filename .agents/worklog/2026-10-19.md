## 2026-10-19 13:50 CST — fixnum fast paths for (scheme base) numeric operators (perf, P1)

- Reviewed the uncommitted fast-path draft against HEAD; it did not build:
  the frontend called a backend registry, so npli (`(npl frontend)`) failed
  with an unbound `register-numeric-alias!`; `numeric.npl` had two paren
  errors, emitted source names instead of `lookup-func` symbols, inverted the
  guard branch (and used `cnel` on a `w` value), and crashed on `car` of `()`
  in alias lookup.
- Alias registry moved to `src/compiler/frontend/numeric-aliases.npl`, shared
  by the compiler and `(npl frontend)`. A call to `(scheme base)`'s
  `+ - * = < <= > >=` (only when the export maps to the library's own
  `integer-*` procedure) inlines the raw primitive when every operand is a
  fixnum and otherwise calls the library procedure, in value and tail
  position.
- Semantic fix: the draft ran the value-position slow path in a nested
  trampoline, so an escaping handler (guard) resumed the caller on the wrong
  C frame (`with-exception-handler: non-current handler exit`). New runtime
  `npl_call_sync` (runtime/trampoline.c) supplies the continuation and pushes
  a sentinel handler that carries a raise out of the nested trampoline, then
  re-raises it non-continuably in the caller's trampoline, as primitive
  errors already do. Valid only for callees that neither capture
  continuations nor call user code; the numeric procedures satisfy this.
  Rejected alternative: keeping aliases in CPS with tail-only fast paths was
  sound but only reached loop 21 s.
- `runtime/control.c` (991 lines) split: the trampoline, CPS application,
  and escape continuations moved to `runtime/trampoline.c`; control.c is now
  705 lines. `npl_parameter_dispatch` became an internal extern.
- New fixture `tests/r7rs/fixtures/numeric-alias-paths` (native, npli, Guile
  oracle): fast and slow paths, fixnum overflow, errors, nested guard,
  dynamic-wind, raise-continuable, call/cc escape, `map`/`apply` with `+`.
