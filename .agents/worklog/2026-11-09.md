## Inline car, cdr, vector-length, vector-ref, vector-set!

New `backend/inline.npl`. Those five rows in `frontend/primitive-table.npl` are
now `special` rows that keep their C symbol. `emit-special-primitive`
emits a tag test (pointer tag, then header word) and loads the field
inline. vector-ref and vector-set! also test the fixnum index against the
length. vector-set! checks the literal flag, stores, and calls
`npl_gc_write_barrier_value` (new in `runtime/alloc.c`). Any failed test
calls the existing C function, which raises the same error object as
before. `c-primitive-row-accepts?` accepts a `special` row without optional
arguments, so `define-c-primitive ... "npl_car"` still resolves.

## Built-in records (design-data section 2)

`define-record-type` and `record-update` are `syntax-rules` macros in
`frontend/derived.npl`, exported by `(npl primitive)` (so import-free
programs and `(scheme base)` share one definition) and by the new
`(npl record)`. Field positions come from two expansion-time core forms,
`%record-index` and `%record-make` (`frontend/expand-record.npl`). The
predicate, accessors, and modifiers call `npl_record_p`/`_ref`/`_set`,
now `special` rows emitted inline (`backend/inline.npl`). The record type
is a record `(npl-record-type name (field ...))` (`npl_record_type`,
runtime/value.c). `lib/scheme/record.scm` deleted.

- `equal?` compares instances of one type field by field, in the bounded
  and the union-find pass (`npl_record_instance_type`, `npl_record_length`).
- write/display: `#<point x: 1 y: 2>`, `#<record-type point>`, datum
  labels through record fields; field values in write syntax, as Guile
  3.0.11 prints them.
- `record-update` (`npl_record_update`): fields checked at run time,
  because the type name is a variable whose fields are unknown while
  expanding (design updated).

Hygiene fix (`frontend/transcription.npl`): in definition-producing macro
output every occurrence of a template identifier got its own alias, so
`(define (name value) value)` returned the global `value` when one existed
at the macro definition site (native and npli printed 99 instead of 5).
Now one alias per name per transcription. Covered by
`src/compiler/tests/records.npl` ("binder named like a global").

Record read in a loop: 128 -> 85 instructions per iteration (vector-ref
69). The rest is the direct call to the accessor; an accessor inliner is a
follow-up. Seed 306,095 -> 310,628 lines (+1.5%).

Fixtures: `records` (native, npli, Guile 3.0.11), `record-extensions`
(oracle none: Guile lacks record-update and prints `#<node v: #0#>` without
the label), `src/compiler/tests/records.npl` (import-free, 10 tests), two
expansion-error contracts, record accessor and modifier SSA checks in the
inline-primitives probe.

## SRFI 125 hash tables (design-data section 3)

Runtime `BOX_HASHTABLE` (`runtime/hashtable.c`, new): open addressing over
one `(hash key value)` entries vector with tombstones; kinds eq, eqv,
equal, string, general. Equal tables compare in C with a bounded walk and
fall back to the library `equal?` for deep or cyclic keys; general tables
call user procedures through the new `npl_apply_sync` (trampoline.c). GC
visits the table's entries and procedures; mutations use the write
barrier. 16 primitive rows, so the compiler can use tables without
imports.

Libraries: `(srfi 125)` (`lib/srfi/125.sld` + `125.scm`, full interface
including deprecated names; equality predicates instead of SRFI 128
comparators) and `(srfi 69)`. Reference text supplied by the user as
`docs/reference/srfi-125.html`. `srfi/` is an installed library prefix.

- A primitive used as a value is a fresh closure per use, so `(eq? p
  eq?)` is #f in native code (npli: #t). make-hash-table recognizes the
  standard predicates with `npl_same_procedure_p` (same code, no
  captures).
- `(srfi 69)` `hash-table-merge!` lets the second table win (Guile and
  SRFI 69), unlike SRFI 125 `hash-table-union!`; its `hash-table-copy` is
  mutable.

Benchmark (1,000,000 eqv inserts and lookups, 100,000 string keys): native
0.33 s CPU, Guile 3.0.11 compiled `(srfi srfi-69)` 1.5 s.

Fixtures: `hash-tables` (oracle none; cyclic, deep, record, flonum, and
rational keys), `srfi-69` (Guile 3.0.11 oracle),
`src/compiler/tests/hash-tables.npl` (import-free, 6 tests, also with a
64 KiB nursery and `NPL_GC_VERIFY=10`). A 20,000-key churn with deletions
also passes under `NPL_GC_NURSERY_BYTES=65536 NPL_GC_VERIFY=20` natively
and in npli.

Found while testing, not changed: native evaluates call operands so that
a side effect in a later operand can be seen by an earlier one
(`(list (vector-ref v 0) (f))` where f mutates v shows the new value
natively, the old one in npli and Guile; the same with the previous seed).
R7RS leaves operand order unspecified, but native and npli differ, which
AGENTS.md treats as a consistency gap. Recorded as an open item.
