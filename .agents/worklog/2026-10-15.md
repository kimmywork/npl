# Worklog 2026-10-15

## 2026-10-15 11:28 CST — bignum output and division (perf)

- Profile of `(display (fact 9000))` (35.6 s native, same in npli): all
  time in `integer_divide` from decimal output, one full division by 10
  per digit, each quotient limb found by a ~30-step binary search (cubic).
- `runtime/numeric.c`: decimal output prints base-10^9 limbs directly
  (linear); other radices divide by radix^k per chunk; one-limb divisors use
  a linear pass; multi-limb division is Knuth's Algorithm D.
- Result: `(fact 9000)` 35.56 s -> 0.04 s (output identical to Guile);
  200 x `(quotient (fact 3000) (fact 1500))` 5.64 s -> 0.17 s (Guile 0.16 s).

Evidence: 730 radix/quotient/remainder/modulo cases and 1509 multi-limb
division cases (random, all-9s, powers, remainder b-1) match Python;
`tools/run_tests.sh --skip-current-fixed-point` all PASS.

## 2026-10-15 17:20 CST — P1 benchmark harness

- `tools/bench.py` + `bench/workloads/*.scm`: 9 R7RS-small workloads (fact,
  tak, fib, loop, lists, vectors, strings, callcc, closures) run under
  nplc-native, npli, Guile `--r7rs`, and Racket, with compile time reported
  separately, median/min-max wall and child CPU time, timeouts, and a
  cross-implementation stdout consistency check.
- Workloads are pure R7RS-small with a shared import header, so the source is
  byte-identical across implementations. Racket gets a 4-line header instead:
  a two-branch `if` macro (Racket requires an `else`; the two-branch form
  falls through to an unspecified value, as R7RS 4.2.5 allows) and
  `string-upcase` (absent from Racket). Both verified against the other three
  implementations by the stdout check.
- `closures` scaled to 50000 iterations: at 2000000 it took 91 s in Racket
  and timed out in Guile and native.
- First full run (host load ~9, single-pass, not a baseline): native is 1.4x
  slower than Guile on `fact` (0.104 s vs 0.079 s) and 42x-140x slower on the
  rest (loop, lists, fib, vectors, callcc, closures, tak, strings); npli
  exceeds 15 s on every workload. No output mismatches.
- Confirmed root cause of the gap: with `(import (scheme base))`, `=`, `+`,
  `-`, `<` compile to calls into the generic varargs NPL procedures in
  `integer.scm` (evidence: the same 5000000-iteration loop is 0.19 s without
  the import and 6.52 s with it). Next: compiler fast paths for fixed-arity
  numeric calls.
