# 2026-11-11

## Compiler adoption step 1: self-compile hot spots (design-data section 5)

Sampling the self-compile (`sample` on the compiler emitting itself) put
the cost in string building, not in the symbol, function, and global
tables the plan named, so step 1 followed the samples.

- `byte-data`/`word-data` (`backend/data.npl`) built a static string's
  ", b 40, b 100, ..." with right-nested `string-append`, copying the rest
  of the text at every character: O(n^2), and the derived syntax source
  (now with `match`) is tens of thousands of characters. Now built by
  halving (`data-units`, runs of 8 characters): same output text.
- After that, the top sample was `identifier-mark-in`: syntax marks were an
  association list searched with `eq?`. `SYNTAX-MARKS` is now an eq hash
  table (`npl_hash_table_ref` with default 0, the old "no mark" value);
  the three resets (`expand-program`, `expand-library-program`, npli
  `make-frontend-session`) make a fresh table with `new-mark-table`. The
  npli session still saves and restores the table object.

Measurements (same host, compiler emitting its own source):

| stage | instructions | user CPU |
|---|---:|---:|
| seed of `d7ff0bd` | 98.20 G | 7.07 s |
| `byte-data` by halving | 27.44 G | 2.47 s |
| syntax marks as eq hash table | 20.29 G | 1.41 s |

Function and global tables (`lk-s`, `backend/state.npl`) did not appear
among the sampled hot spots; they stay association lists until a sample
shows them.

Evidence: gen1 == gen2 after each change; strict relay
(`tools/update_current_ssa.sh`) PASS, `bootstrap/current.ssa` 315,561
lines, SHA `8abe2791b9bec3237aa0f5304d5a53b55fde0a7c9d2948993411f0d7a78c8e78`;
`tools/run_tests.sh --skip-current-fixed-point` all suites PASS (57);
`tools/check_linux.sh --skip-current-fixed-point` all suites PASS (57).

## Compiler adoption step 1b: hashed global layer in value environments

Re-sampled with the step 1 seed: the top spot was
`lookup-value-binding-key`. `predeclare-globals` put each of the
compiler's ~1,000 globals into the value environment as its own entry, so
every lookup of a name bound further out (every primitive, every
library-level name) walked all of them. `predeclare-globals` now adds one
global layer `(#f #f table)` (`value-binding-layer`, `syntax.npl`): a
string hash table from name to its `((mark . emitted) ...)`, innermost
first, with the same bindings as before. Lookups consult it in place of
those entries; the table is never changed after it is built, so
environments stay persistent (npli sessions, library imports, alias
layers unaffected). The definition-name checks moved to
`checked-identifiers-into` with the same messages.

| stage | instructions | user CPU |
|---|---:|---:|
| step 1 seed (`6930139`) | 20.29 G | 1.41 s |
| global layer | 14.06 G | 1.02 s |

Evidence: gen1 == gen2; all 80 test programs (`src/compiler/tests/*.npl`,
fixture `native.npl` files) emit byte-identical SSA with the step 1 and
the new compiler; strict relay PASS, `bootstrap/current.ssa` 317,585
lines, SHA `4cca8e4426eb8f5012ad61b4084eb554e4cab70835df95ad75b0fc93b7a7d7a6`;

## Compiler adoption step 2: compiler-internal state as records

A read-only survey ranked the compiler's hand-written vector and list
structures by how cleanly they convert. The four cleanest are now
`define-record-type` records with the accessor names unchanged, so no
call site changed:

- syntax capture (`syntax.npl`, was `(name path value)`):
  `syntax-capture`;
- syntax-rules transformer (`syntax.npl`, five-element list built only in
  `parse-syntax-rules`): `syntax-transformer`;
- `SELF-FUNCTION` (`backend/tail.npl`, five-element list built only in
  `program.npl emit-hoisted-body`): `self-function`;
- direct-call entry (`frontend/direct-calls.npl`, eight-element vector):
  `direct-call-entry`, with `set-` modifiers replacing the seven fixed-index
  `vector-set!` sites (reason, calls, tails, mark, assigned).

Measured one at a time from the step 1c seed:

| change | instructions | seed lines |
|---|---:|---:|
| step 1c seed (`457a6f0`) | 12.49 G | 317,369 |
| capture | 12.50 G | 317,496 |
| transformer | 12.54 G | 316,930 |
| `SELF-FUNCTION` | 12.56 G | 316,869 |
| direct-call entry | 12.60 G | 316,843 |

About +1% instructions in all (12.61 G after the reorder below), as
expected from a record field read costing more than `vector-ref`

Found while gating: the first relay passed, but `tools/build_toolchain.sh`
then failed (its output had been piped to `tail -1`, hiding exit 1): npli

## Compiler adoption step 3: match pilot, not adopted

Pilot: `control-cps-expression` (`frontend/control.npl`, the control
conversion dispatch over core tags 213-222) and its `if` and `set!`
helpers rewritten with `match`; source -22 lines. Measured against the
step 2 seed (`1afdaa2`):

| measure | step 2 seed | pilot |
|---|---:|---:|
| seed lines | 316,843 | 318,487 (+1,644) |
| top-level lambdas in the seed | 4,585 | 4,635 (+50) |
| self-compile instructions | 12.68 G | 12.79 G (+0.8%) |

The one dispatch grew from about 490 SSA lines to about 2,100. Shinn's
expansion gives every clause a failure continuation `(lambda () ...)`
(each test's failure branch shares it), and the CPS compiler turns those
and the pattern `let`s into closures: an application, the commonest core
form, falls through nine clauses. That fails design-data section 4's rule
that adopting `match` must not grow the seed by more than the code it
removes, so the pilot was reverted (diff kept outside the tree) and the
compiler keeps its hand-written dispatch. Adopting `match` in the compiler
needs a cheaper expansion first; decision left to the user.

## Control conversion: simple if tests stay in place

Found while re-running the `match` pilot with a closure-free clause
expansion (`%match-clause`, set aside, see below): the compiler's own code
blew up exponentially (2 clauses ~8 k SSA lines, 8 clauses ~108 M).
`control-cps-if` (`frontend/control.npl`) converted any test that was not
`control-simple?`, including an `if` of simple parts such as
`(if (and a b) ...)`. Converting such a test sends the continuation (the
whole outer `if`) to both branches of the inner one, and `control-send`
inlines a one-parameter continuation there, so each such test doubled the
code after it. `control-simple-test?` now accepts an `if` whose test and
branches are simple tests, and `control-transform-simple` passes such an
`if` through; the backend's `emit-if` already evaluates an `if` as a
value. No other code path changes.

The fix also applies to the compiler itself, which uses `and`/`or` tests
throughout:

| measure | before | after |
|---|---:|---:|
| seed lines | 316,843 | 288,995 (-8.8%) |
| self-compile instructions | 12.58 G | 12.29 G |
| SSA lines of the 80 test programs | 4,683,596 | 4,331,126 (-7.5%) |

62 of the 80 test programs emit different (smaller) SSA.

Seed transition in two steps, as on 2026-10-22, 10-27, and 11-03: the
change is to code generation, so gen1 (the old seed compiling the new
source) differs from gen2. The relay's gen2 == gen3 and equals the
hand-built gen2; it was installed, then the strict relay passed.

Bench (`tools/bench.py --runs 3 --scaled`, CPU, old -> new compiler):
native all within +-5% (fib 0.133 -> 0.127, loop 0.359 -> 0.340, vectors
0.468 -> 0.476); npli within run-to-run noise (vectors 53.7 -> 56.9 with
overlapping ranges 52.3-61.1 and 55.3-63.4; tak 17.5 -> 15.7); native
compile time lower on every workload (vectors 2.24 -> 1.12 s); no output
mismatch.

Evidence: strict relay PASS after the two-step transition,
`bootstrap/current.ssa` 288,995 lines, SHA
`3ecd124ae7dcfdceb1ce3f0fc3f9861da6c70a9bbcff00d2b49c1596d43c8104`;
`tools/build_toolchain.sh` exit 0; `tools/run_tests.sh
--skip-current-fixed-point` all suites PASS (57); `tools/check_linux.sh
--skip-current-fixed-point` all suites PASS (57).

## Control conversion: simple lets stay lets

Second finding from re-running the `match` pilot (see above): in the pilot
the dispatch became one 1,443-line closure, and the reason was not the
clause expansion but `control-cps-let`. Every `let` whose body is not
direct-safe became a closure applied to the inits, so the `let` a `match`
clause expands to (a closure body) and the `let`s around it became another
closure level each.

`control-cps-let` now keeps a let whose inits are all simple
(`control-simple-list?`) as core form 214 around the converted body: the
inits cannot capture a continuation while they are evaluated, so no
closure is needed. A continuation that is not a variable is first bound to
a fresh name (`_npl_let_k_`), because the body may send to it from several
places (both branches of an `if`) and `control-send` copies an inline
continuation into each.

| measure | before | after |
|---|---:|---:|
| seed lines | 288,995 | 261,586 (-9.5%) |
| top-level lambdas in the seed | 4,215 | 3,439 |
| self-compile instructions | 12.28 G | 11.13 G (-9.4%) |

Control-flow suites checked after the change: match, continuations,
dynamic-wind, guard, exceptions, multiple-values, parameters, promises,
derived-forms, explicit-control, records, hash-tables all PASS; fixtures
dynamic-extent, records, match, match-extensions, definition-macros, lists,
closure-captures, named-loops identical. Seed transition in two steps
(gen1 != gen2, gen2 == gen3), as above.

Bench (`--runs 3 --scaled`, before -> after): native within noise except
lists 1.768 -> 1.846 s (+4.4%, ranges 1.776-1.799 and 1.856-1.939); npli
