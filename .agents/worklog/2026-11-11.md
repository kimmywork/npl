# 2026-11-11

## Compiler adoption step 1: self-compile hot spots (design-data section 5)

Sampling the self-compile (`sample` on the compiler emitting itself) put
the cost in string building, not in the symbol, function, and global
tables the plan named, so step 1 followed the samples.

- `byte-data`/`word-data` (`backend/data.npl`) built a static string's
  ", b 40, b 100, ..." with right-nested `string-append`, copying the rest
  of the text at every character: O(n^2), and the derived syntax source
  (now with `match`) is tens of thousands of characters. Now built by
  halving (`data-units`, runs of 8 characters): same output text.
- After that, the top sample was `identifier-mark-in`: syntax marks were an
  association list searched with `eq?`. `SYNTAX-MARKS` is now an eq hash
  table (`npl_hash_table_ref` with default 0, the old "no mark" value);
  the three resets (`expand-program`, `expand-library-program`, npli
  `make-frontend-session`) make a fresh table with `new-mark-table`. The
  npli session still saves and restores the table object.

Measurements (same host, compiler emitting its own source):

| stage | instructions | user CPU |
|---|---:|---:|
| seed of `d7ff0bd` | 98.20 G | 7.07 s |
| `byte-data` by halving | 27.44 G | 2.47 s |
| syntax marks as eq hash table | 20.29 G | 1.41 s |

Function and global tables (`lk-s`, `backend/state.npl`) did not appear
among the sampled hot spots; they stay association lists until a sample
shows them.

Evidence: gen1 == gen2 after each change; strict relay
(`tools/update_current_ssa.sh`) PASS, `bootstrap/current.ssa` 315,561
lines, SHA `8abe2791b9bec3237aa0f5304d5a53b55fde0a7c9d2948993411f0d7a78c8e78`;
`tools/run_tests.sh --skip-current-fixed-point` all suites PASS (57);
`tools/check_linux.sh --skip-current-fixed-point` all suites PASS (57).

## Compiler adoption step 1b: hashed global layer in value environments

Re-sampled with the step 1 seed: the top spot was
`lookup-value-binding-key`. `predeclare-globals` put each of the
compiler's ~1,000 globals into the value environment as its own entry, so
every lookup of a name bound further out (every primitive, every
library-level name) walked all of them. `predeclare-globals` now adds one
global layer `(#f #f table)` (`value-binding-layer`, `syntax.npl`): a
string hash table from name to its `((mark . emitted) ...)`, innermost
first, with the same bindings as before. Lookups consult it in place of
those entries; the table is never changed after it is built, so
environments stay persistent (npli sessions, library imports, alias
layers unaffected). The definition-name checks moved to
`checked-identifiers-into` with the same messages.

| stage | instructions | user CPU |
|---|---:|---:|
| step 1 seed (`6930139`) | 20.29 G | 1.41 s |
| global layer | 14.06 G | 1.02 s |

Evidence: gen1 == gen2; all 80 test programs (`src/compiler/tests/*.npl`,
fixture `native.npl` files) emit byte-identical SSA with the step 1 and
the new compiler; strict relay PASS, `bootstrap/current.ssa` 317,585
lines, SHA `4cca8e4426eb8f5012ad61b4084eb554e4cab70835df95ad75b0fc93b7a7d7a6`;
`tools/run_tests.sh --skip-current-fixed-point` all suites PASS (57);
`tools/check_linux.sh --skip-current-fixed-point` all suites PASS (57).

## Compiler adoption step 1c: backend function and global tables

The next profile's runtime hot spots (string comparison in
`npl_require_bytes_internal`, `npl_string_same_chars_internal`) came
mostly from `lookup-func` and `lk-s`: the backend tables the plan named.
`FUNCS`, `FUNC-ARITIES`, and `GLOBS` (`backend/state.npl`) are now string
hash tables; `register-glob` replaces the inline cons in `variable-def`.
A later registration of a name still wins; misses still return `""` and
`0`. `SYMS` stays a list: `print-static-symbols` emits it in insertion
order.

| stage | instructions | user CPU |
|---|---:|---:|
| step 1b seed (`4ee05fb`) | 14.06 G | 1.02 s |
| backend tables hashed | 12.49 G | 0.90 s |

Evidence: gen1 == gen2; all 80 test programs emit byte-identical SSA with
the step 1b and the new compiler; strict relay PASS,
`bootstrap/current.ssa` 317,369 lines, SHA
`7501b4645728e9030bd04ba689ccf8cd8defc3706800b59576b9606ba1595490`;

`tools/check_linux.sh --skip-current-fixed-point` all suites PASS (57).

The remaining profile is allocation, GC sweeping, string building, and
reading source files; none is a table lookup, so step 1 ends here.

## Compiler adoption step 2: compiler-internal state as records

A read-only survey ranked the compiler's hand-written vector and list
structures by how cleanly they convert. The four cleanest are now
`define-record-type` records with the accessor names unchanged, so no
call site changed:

- syntax capture (`syntax.npl`, was `(name path value)`):
  `syntax-capture`;
- syntax-rules transformer (`syntax.npl`, five-element list built only in
  `parse-syntax-rules`): `syntax-transformer`;
- `SELF-FUNCTION` (`backend/tail.npl`, five-element list built only in
  `program.npl emit-hoisted-body`): `self-function`;
- direct-call entry (`frontend/direct-calls.npl`, eight-element vector):
  `direct-call-entry`, with `set-` modifiers replacing the seven fixed-index
  `vector-set!` sites (reason, calls, tails, mark, assigned).

Measured one at a time from the step 1c seed:

| change | instructions | seed lines |
|---|---:|---:|
| step 1c seed (`457a6f0`) | 12.49 G | 317,369 |
| capture | 12.50 G | 317,496 |
| transformer | 12.54 G | 316,930 |
| `SELF-FUNCTION` | 12.56 G | 316,869 |
| direct-call entry | 12.60 G | 316,843 |

About +1% instructions in all (12.61 G after the reorder below), as
expected from a record field read costing more than `vector-ref`
(section 2); the seed shrank by ~500 lines.

Found while gating: the first relay passed, but `tools/build_toolchain.sh`
then failed (its output had been piped to `tail -1`, hiding exit 1): npli
compiles the frontend as the `(npl frontend)` library, where a name
defined by macro output is not bound before the macro use, and
`syntax-transformer` was defined after `parse-syntax-rules` (`unbound
identifier: make-syntax-transformer`). nplc's self-compile was unaffected.
The record is now defined before its first use, with a comment saying why.

Not converted (survey): syntax environment entries (three shapes on the
hottest path, saved in the npli session), backend environment entries
(hottest backend lookup, raw `car` name reads), primitive rows (built at
startup, a hand-built row in `c-primitives.npl`), the npli session vector,
and library entry info, whose `parts` feeds npli's library checksum.

Evidence: gen1 == gen2 after each change; all 80 test programs emit
byte-identical SSA with the step 1c and the new compiler; strict relay
PASS, `bootstrap/current.ssa` 316,843 lines, SHA
`8fd6419623bb01f73fb583c896a785ed6ed66ceb98a6f6385afba308ea52e907`;
`tools/build_toolchain.sh` exit 0; `tools/run_tests.sh
--skip-current-fixed-point` all suites PASS (57); `tools/check_linux.sh
--skip-current-fixed-point` all suites PASS (57).
