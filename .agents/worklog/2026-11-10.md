# 2026-11-10

## match (design-data section 4)

Alex Shinn's public-domain `syntax-rules` matcher (as Guile 3.0 ships it,
`ice-9/match.upstream.scm`) in `frontend/derived-match.npl`, parsed with the
derived syntax (`derived-syntax-forms`). Forms: `match`, `match-lambda`,
`match-lambda*`, `match-let` (named too), `match-let*`, `match-letrec`,
`match-define` (new). Exported by `(npl primitive)` and the new
`(npl match)` (`lib/npl/match.sld`); import-free programs have it.

Import-free adaptations: literal and quoted atoms compare by kind
(`%match-literal`: inline `eq?` for symbols, booleans, chars, `()`,
fixnums; `eqv?`, `string=?`, byte loop otherwise); quoted pairs and vectors
match part by part; list length (cycle-safe), reverse, and `vector->list`
are inline loops; `%match-length` counts at expansion. The `let-syntax`
tricks became `%match-identifier?`, `%match-member?`, `%match-ellipsis?`
(`frontend/expand-match.npl`): NPL's `let-syntax` does not splice, so
`match-define` could not define through them. A repeated pattern variable
is an expansion error (Shinn/Guile: `equal?` test; no import-free
`equal?`). `($ type p ...)` matches records by position, raising
`match: too many field patterns` past the last field (inline record access
is not range-checked). A failed match raises `match: no matching pattern`
with the value as irritant.

Frontend defects found and fixed on the way (the uncommitted lexer and
syntax-rules changes found at the start of the session are part of this):

- Alias environments copied the macro's definition environment at every
  expression transcription; continuation-passing macros nest hundreds deep,
  so failed lookups scanned the globals once per level (one `or` pattern:
  86 s to compile). Now one alias layer entry per transcription
  (`lookup-value-binding-key`, `lookup-macro-cell-key`): 0.1 s. The copy
  also reversed the definition environment, so a template saw the outer of
  two shadowed bindings (native printed 1, Guile 2); fixed with it.
- Derived syntax was expanded without prebound keywords; a derived macro
  could only use earlier ones. `expand-derived-syntax` (`toplevel.npl`) is
  now the one entry for programs, libraries, and npli sessions.
- Literal identifiers: `=` from `(scheme base)` (integer-equal) did not
  match the primitive `=`, and in npli a free `not` did not match the
  `(npl primitive)` one. `literal-binding-key` maps both to the primitive.
- `define-values` returned expanded code that the body or top level
  expanded again (with imports: `unbound identifier: _npl_lib_1_list`, also
  with the previous seed); it now returns source, and macro output that is
  a `define-values` is spliced like other definitions.
- `resolve-marked-walk` copied datum atoms (tagged pairs) as pairs: a
  string, char, vector, or boolean literal in a definition-producing macro
  broke compilation (also with the previous seed).
- syntax-rules: `()` matches a nested `(p ...)` subpattern; the lexer
  accepts `$ & ^ ~` in identifiers (R7RS 7.1.1).
