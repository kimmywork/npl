# 2026-11-17

## Procedural syntax-case and phase-1 definitions

- Added `src/compiler/frontend/syntax-eval.npl` (compile-time evaluator core),
  `syntax-eval-syntax.npl` (syntax-case/with-syntax/quasisyntax and entry
  points), and `syntax-primitives.npl` (primitive procedure table).
- `parse-syntax-rules` now returns either the existing syntax-rules
  transformer, the declarative syntax-case lowering, or a
  `procedural-transformer`.
- Transformer bodies run over the frontend datum representation, so
  `quote`, `syntax`, and syntax helpers share one representation and template
  expansion reuses `clone-template`.
- Added syntax helpers: `identifier?`, `syntax->datum`, `datum->syntax`,
  `syntax-e`, `syntax->list`, `free-identifier=?`, `bound-identifier=?`,
  `generate-temporaries`, and `syntax-violation`.
- `begin-for-syntax` and `(for-syntax ...)` evaluate definitions into a
  phase-1 value environment used by later transformers.
- Added `syntax-case-procedural` suite (14 tests) and registered it in
  `tools/check_full_compiler.sh` (64 suites).
- `nplc`, `npli`, and the shared `(npl internal frontend)` include the new
  modules.
