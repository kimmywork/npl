## 0.1.2 I3 completion: forward calls, collections, maps, bitvectors

- Fixed the compiler's forward reference to a value-defined global. The
  backend registers every top-level variable slot before emitting forms, so
  a procedure that calls a later `(define name (lambda ...))` or
  `(define name (case-lambda ...))` emits an indirect call instead of
  `unknown builtin or unbound`. This is the R7RS 5.1 library/program body
  rule and the actual SRFI 146 port blocker.
- Added `src/compiler/tests/forward-references.npl` and a forward-call case
  to the native/evaluator differential fixture. Relayed
  `bootstrap/current.ssa` (269,201 lines,
  SHA-256 `68ceaee686e21ffaa836fe93df46ca95600523c34c81381bf5a7eba71ed13d6a`).
- Renamed the set/bag record accessors to `set-key-comparator` and
  `bag-key-comparator`; the exported `set-comparator`/`bag-comparator`
  values had collided with accessor definitions that earlier uses relied on.
- Added `(npl data collection)` / `(srfi 44)` for lists, vectors, and
  strings, with generic collection folds, size, count, copies, and the
  concrete sequence operations. Bags, sets, maps, and dictionaries are
  documented as outside this increment.
- Ported the SRFI 146 reference implementation as `(npl data map)` /
  `(srfi 146)`: persistent red-black tree mappings, ordered mappings,
  ranges, submapping comparisons, folds, and value comparators.
- Implemented `(npl data bitvector)` / `(srfi 178)`: bytevector-backed
  bitvector views, constructors, accessors, folds/maps, conversions,
  bitwise operations, shifts, counts, and bit-field operations.
- Suites: `forward-references` 4, `srfi-44` 27, `srfi-146` 33,
  `srfi-178` 30. Gate covers 54 compiler suites; alias-export parity passes.
