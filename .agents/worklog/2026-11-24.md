## Library export origins and test coverage

- `(tools libraries)` now records each definition's kind (`define`,
  `define-syntax`, `define-values`, `define-record-type`,
  `define-c-primitive`, `define-c-function`) and exposes
  `check-export-origins`.  It follows the import graph for every external
  name; a re-export that reaches the same origin is not a conflict.  A
  runnable report is `tools/export-origins.npl`.
- Current export-origin report: 69 names have different final origins, all
  in intentional SRFI/NPL variant overlaps (for example SRFI 13 vs 125
  `string-hash`, SRFI 140 immutable strings, SRFI 44 collection).  R17's
  `delete-directory` no longer appears because `(npl unix)` re-exports
  `(npl process)`'s binding.
- `check-library-test-coverage` now reports every `lib/npl` and `lib/scheme`
  library not in `(coverage-libraries)`, and classifies it by assertion
  coverage: `full` (all exports asserted/reported), `partial` (some), or
  `uncovered`.  Only assertion/report bodies count, not imports or bare
  mentions.  The uncovered library ratio must stay below 30%.
- Per-library local export coverage: for each `lib/npl` and `lib/scheme`
  `.sld`, exports re-exported from a dependency are excluded; at least 80%
  of the library's own exported definitions must appear in an
  assertion/report form.  The ratio and missing names are printed on every
  run.
- Removed the hand-maintained `(coverage-libraries)` list: the scan now
  covers every `lib/npl`, `lib/scheme`, and `tools` `.sld` automatically.
  Re-export-only libraries are skipped; assertion coverage is computed from
  the library's own definitions only.
- Added `(npl util)` and `(npl test util)` for shared string/path/tool
  helpers, and `check-duplicate-definitions` for private top-level
  definitions.  Included definitions are tracked by source file, so one
  shared kernel included by several libraries is not a duplicate.  Current
  duplicate scan: PASS.
- Current automatic coverage: 56 libraries with local exports; library
  coverage 49 covered (23 full, 26 partial), 7 uncovered (12%, limit 30%).
  Symbol coverage is below the new 80% rule for 27 libraries; the run prints
  each library, its covered/total count, and missing names.  The full gate
  now reports `suite failures: 1` for these symbol gaps until assertions are
  added; duplicate definitions pass.
- `runtime/port.c` split into `port.c` (764 lines) + `port-ready.c`
  (71 lines: char-ready?/u8-ready? readiness over stdio/poll); the split
  initially broke `char-ready?` (require_mode kind 0 always failed the
  mode check), caught by the `text-io-time` fixture and fixed by passing
  `NPL_PORT_INPUT` as the kind.  `tools/toolchain.sld` split into
  `toolchain.sld` (640) + `toolchain/install.scm` (197).  Both are back
  inside the 800-line limit.
- An in-compiler two-source import-conflict diagnostic (binding origin
  tracking) was attempted for R17 and reverted: with it, the npli evaluator
  failed at startup (`expand-library-program`'s `expand-derived-syntax`
  reported a leaked runtime form; `(car result)` was the primitive name
  string `make-environment`).  Reverted after a clean-seed A/B confirmed the
  frontend change was the cause; the compiler diagnostic keeps the binding
  name, and the static `check-export-origins` report provides the
  symbol -> libraries mapping.  The seed is back at the round-2 state
  (SHA-256 in Accepted Seed).
- Existing fixes to reach 80%: shared `(npl util)` helpers and a
  `tests/unit/tools-util.npl` covering both shared utility libraries.
