## Review: syntax-rules ellipsis leniency and lambda shorthand (00:59 CST)

- Added `.agents/reviews/2026-11-14-syntax-rules-ellipsis-and-lambda-shorthand.md`.
  Read-only investigation of a user `\` lambda-shorthand macro error in npli;
  no source changes. The error is a rule-order issue in the macro, not a
  matcher bug.
- N1: `syntax-rules` accepts multiple ellipses at one level
  (`src/compiler/frontend/syntax.npl:310` validation, `:555` greedy
  backtracking; the last separator wins). Guile and Racket reject such
  patterns. A token scan of 435 repo sources found no such pattern, so
  tightening to R7RS would not break existing code. Decision open:
  tighten, or document as an extension.
- N2: a bare `\` identifier is read by npli (`runtime/read.c`) but rejected
  by nplc (`src/compiler/reader/lexer.npl:444`, no line/column).
- N3: the import-free environment (npli and nplc) lacks `assv`/`assoc`;
  scope is undocumented.
- Recorded portable, curried, and reject-multiple-`=>` macro versions with
  npli/nplc/Guile/Racket evidence, plus a Racket comparison (curried
  `define`, `curry`, `syntax-parse`).

## Review: macro system deep review and syntax-case assessment (01:34 CST)

- Added `.agents/reviews/2026-11-14-macro-system-review.md`. Read-only;
  29 probes run on npli, nplc, and Guile.
- High: M1, a single `define` produced by a macro does not join the body
  scope (`expand.npl:69`, `:385`); nplc rejects `(define (f) (def get) (get))`
  and miscompiles it when a global `get` exists (runtime
  `wrong number of arguments: -1`); npli is correct; present on master.
  M2, depth-0 pattern variables are rejected inside ellipsis templates
  (`syntax.npl:686`), contrary to R7RS 4.3.2.
- Medium: M3 alias-layer any-mark lookup lets macro-introduced bindings
  capture user identifiers; M4 npli/nplc disagree on top-level
  macro-introduced definitions; M5 a body macro defined after a lambda that
  uses it is rejected; M6 core syntax is not exported from `(scheme base)`
  for `only`/`except`/`rename`/`prefix`.
- Low: M7 template depth checked only at use; M8 quadratic transcription
  (16,000 elements 2.03 s vs 0.17 s); M9 diagnostics; M10 SRFI 149
  template extensions absent.
- syntax-case and syntax-parse are not needed now: no roadmap item depends
  on them, and they need compile-time evaluation in nplc, a rebuilt
  identifier model (M3), and source spans. Suggested order: M1/M2, then
  M3-M6 and N1, D1 spans, optional SRFI 149, then SRFI 211 er/ir macros
  before any syntax-case.
