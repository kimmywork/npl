# 2026-11-05

## closures: bignum add and multiply in place (perf)

User direction: close the gap to Guile and Racket on lists, closures, and
strings. Profile (`sample`) of closures: 70% `npl_number_mul`, 9%
`integer_add_magnitudes`. The workload's accumulator doubles each
iteration (~2^50000 by the end), so every `(* x 2)` and `(+ x 1)` is a
bignum operation; it is bignum-bound, not closure-bound.

`runtime/numeric.c`:
- `alloc_integer` / `finish_integer`: add and multiply write the result
  limbs into the bignum they return, instead of a calloc'd buffer that
  `box_integer_limbs` copied and freed. Operands stay referenced from a
  volatile local while the result is allocated (a view's limbs point inside
  the operand, which the conservative scan does not count).
- Multiply: rows over the shorter operand (a small multiplier is one pass),
  view fields hoisted into locals, `(* x 1)` and `(* 1 x)` return the other
  operand (the library fold starts at 1).
- Add: the longer operand on the left; after the shorter one, the carry is
  propagated and the rest is copied with `memcpy`.

Bench (CPU s, 3 repeats as in bench.py --scaled; same compiler, old and new
runtime):

|---|---:|---:|---:|---:|
