## 2026-10-27 CST — P6b define-c-function with generated C stubs

Decided with the user (2026-10-24/25): nplc builds stubs automatically and
`nplc --emit=c-stubs` writes them for npli; nplc links the same stubs;
pointer-out results return as extra values.

- `(define-c-function name "c_symbol" (type ...) -> result)`
  (`src/compiler/frontend/c-functions.npl`, new): types int, long, int64,
  size_t, double, bool, string, pointer, pointer-out (argument only), void
  (result only). Records one entry per C symbol in DECLARED-C-FUNCTIONS
  (a second, different signature is an error) and registers the stub
  `npl_cfn_<c_symbol>` as a C primitive, so calls, value uses, imports,
  and npli's symbol lookup are those of define-c-primitive. More than one
  result uses the `values` result type.
- `src/compiler/backend/c-stubs.npl` (new): writes a C99 file, one stub per
  entry: check and convert every argument first, copy strings, call, box
  the results, free the copies last (a result may point into one).
- `runtime/ffi.c`: npl_ffi_to_int64/uint64 (range checked, bignums through
  decimal text), to_double, to_bool (only #f is false), to_pointer,
  check_string (no NUL), copy_string, free, and from_* boxing; npl.h
  declares them.
- `src/compiler/driver.npl`: kind `c-stubs` (stdout or -o; expansion runs
  before the output is opened). An exe build's SSA child run also writes
  the stubs (internal `--c-stubs-file`), so the program is expanded once;
  the driver compiles them with `-I` the installed `include/npl` (or
  `NPL_INCLUDE`) and links them before the -l libraries; failure reports
  "cc (c stubs)". npli's lookup error names the stub and how to build it.

## O1 inline fixnum arithmetic (perf)

- `src/compiler/backend/numeric.npl`: two-operand `+`/`-` steps add or
  subtract the tagged values directly (fixnum = value << 2, tag 0) and test
  overflow by sign: add `((s^a)&(s^b)) < 0`, sub `((a^b)&(a^s)) < 0`. On
  overflow, or when an operand is not a fixnum, the step calls the existing
  `npl_number_add/sub`, which builds the bignum. Folds test tags again after
  the first step (an intermediate may be a bignum). `+` has no `0` seed:
  `(+)` is 0, `(+ x)` is x on the alias fast path (operands already proven
  fixnums) and one runtime call on the import-free path (it must reject a
  non-number). `*` still calls `npl_number_mul`.
- `src/compiler/backend/expression.npl`: comparisons on two fixnums are one
  `csltl`/`cslel`/`ceql`/... on the tagged operands; otherwise
  `npl_number_compare`. A `checked` flag skips the tag test on the alias
  fast path, where the combined guard already ran.
- QBE pitfall: QBE propagates constants into the dead fast path and folds
  "static box address + tag - constant" into a negative relocation addend
  (`_rational_N@page+-3`), which the Mach-O arm64 linker rejects
  (`numeric-alias-paths` failed to link). Each temporary operand of the
  inline add/sub is masked with `and x, -4` (identity on fixnums; QBE does
  not fold an address through it). Masking only temporaries paired with a
  literal was not enough: either side becomes constant only after
  propagation.
- `runtime/numeric.c`: `npl_number_add/sub/compare` test fixnums first
  (before complex, inexact, rational); also helps npli's primitives.
- `tools/bench.py`: `--repeat N` calls `(bench-main)` N times per run;
  `--scaled` uses the P7 per-workload counts (startup amortized).
- Fixture `tests/r7rs/fixtures/integer-arithmetic` (native, npli, Guile):
  new `boundary-results` at 2^61-1 and -2^61 for add, sub, negate, folds,
  alias and import-free paths, mixed bignum, inexact, rational, compare
  chains; expected output from Guile.
