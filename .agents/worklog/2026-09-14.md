## 11:35:49 CST

Closed the planned two-stage bootstrap transition for static binary64 literals without changing the permanent bootstrap compiler or `bootstrap/bootstrap.ssa`. The initial current compiler could not execute the new static-float path, so it first emitted a seed that recognizes the compiler-only `npl_inexact_bits` primitive without invoking it. That primitive exposes an inexact value's IEEE binary64 payload as an exact decimal integer; after the seed transition, the restored backend path uses it to emit the `NplFloat` layout as QBE `{ w 5, w 1, l <payload> }`, rather than unsupported QBE floating data syntax. A second strict relay from that seed produced byte-identical gen1/gen2/gen3.

Evidence:
- `build/float-static-final-relay/` passes the strict three-generation relay: 350,754 SSA lines, SHA-256 `b52e13c56d1fb46257c295a8b29cc42776f94f43d211b1c64327ee5cccee0027`.
- The accepted `bootstrap/current.ssa` independently compiles static `0.5`, `-1.5`, infinities, and NaN; `0.5` emits `data $float_113 = { w 5, w 1, l 4602678819172646912 }`, while high-bit payloads such as `-1.5` also QBE-compile and link. The executables print the canonical expected forms.
- `bash tools/check_numeric_reference.sh` passes: 12,818 runtime checks, 2,244 Guile reference results, and four expected zero-divisor errors. `bash tools/check_full_compiler.sh`, `bash tools/check_repl.sh`, and the rational native/REPL/Guile fixture pass; `git diff --check` passes.

The helper is a compiler implementation mechanism, not a public API. A dedicated native/REPL/Guile inexact fixture is still required before claiming bounded inexact language integration; radix parsing/printing, complex numbers, complete R7RS number-tower conformance, and the primitive registry audit remain open.
