# 0.1.3 FFI, POSIX, Time, and Threads

Status: accepted direction, 2026-11-13, after merging 0.1.2 (PR #3) and
reviewing `.agents/reviews/2026-11-12-features-and-roadmap.md` with the
Appendix review opinions. This plan supersedes the 0.1.3 sketch in
[0.1.2-srfi](0.1.2-srfi.md) and keeps the 0.1.x release line.

Scope:

- FFI memory: C arrays, scalar views, and C structs.
- `(npl time)` / `(srfi 19)`.
- `(npl unix)` / `(srfi 170)` (full POSIX surface, split across PRs).
- `(npl thread)` / `(srfi 18)` and `(npl atomic)` / `(srfi 230)`.
- Full SRFI 226 after threads.
- The accepted review findings from the Appendix review as a hardening
  increment before the runtime work.

## Macro foundation (M0, added 2026-11-16)

0.1.2 I3 exposed macro-system defects that block the 0.1.3 libraries. The
macro work now precedes the FFI work:

- M0a: `syntax-rules` conformance fixes
  - single `define` transcribed by a macro joins the body/top-level scope
  - depth-0 pattern variables are allowed under ellipsis templates
  - two-pass body expansion: later `define-syntax` is visible in earlier
    lambda bodies, but not in earlier definition initializers
  - template ellipsis depth is checked when the macro is defined
  - same-level multiple ellipses are rejected (R7RS)
  - template-introduced top-level definitions get per-expansion names, so
    nplc and npli both behave like Guile for repeated macro definitions
  - bare `\` is rejected as an identifier by nplc and npli; nplc reports
    the source position
- M0b (implemented 2026-11-16): SRFI 46 tail patterns/custom ellipsis and
  SRFI 149 template extensions (adjacent ellipses and deeper template
  repeats); feature identifiers `srfi-46`, `srfi-149`,
  `srfi-149-compatible`; `(srfi 149)` exports the core `syntax-rules`
  binding.
- M1: identifier source-mark history and syntax-object foundation. The M3
  hygiene capture bug is fixed; full syntax objects remain.
- M2 (implemented 2026-11-16/17): declarative `(lambda (stx) (syntax-case
  stx (literal ...) [pattern (syntax template)] ...))` lowers to the existing
  syntax-rules matcher/template engine. Other lambda transformers are
  evaluated by `frontend/syntax-eval*.npl`: lexical frames, core forms,
  primitives, `syntax-case`/`with-syntax` clause environments,
  `syntax`/`quasisyntax`, and the syntax helpers (`identifier?`,
  `syntax->datum`, `datum->syntax`, `syntax-e`, `syntax->list`,
  `free-identifier=?`, `bound-identifier=?`, `generate-temporaries`).
  `begin-for-syntax` and `(for-syntax ...)` define phase-1 values and
  syntax-rules/procedural phase macros; transformer bodies may use
  `let-syntax`/`letrec-syntax`. `tests/fixtures/syntax-case` checks the
  R6RS syntax-case surface on nplc, npli, and Guile, and
  `syntax-case-npl` checks the NPL extensions on nplc and npli.
  Remaining: full syntax objects with arbitrary mark histories.
- M4 (implemented 2026-11-23; lambda shorthand and library migration):
  `(npl lambda)` provides `λ` and `fn` with ordinary formals and the
  single-segment arrow form `(λ x y => body)`; currying uses nested lambdas.
  `(npl data stream)` / `(srfi 41)` now uses the reference implementation's
  procedural syntax-case pattern matcher with fenders (`stream-match`). This
  M4 is separate from the review's M4 (top-level macro-introduced
  definitions), which M0a already covers.

`check_full_compiler.sh` covers the formal macro fixtures. The review probe
corpus remains under `.agents/reviews/probes/` as evidence and is migrated
incrementally into `src/compiler/tests/` and `tests/fixtures/`.

## Increments

### H1: runtime and reader hardening (implemented 2026-11-23)

Implement the accepted items above. No new library API.

Verification: existing gate plus differential rest-arity, record-bounds,
reader-fuzz, and single-form reentry fixtures; `check_gc.sh` for runtime
changes; seed relay for the lexer change.

Implementation: record accessors validate 1 <= index < length in both the
inline backend path and `npl_record_ref`/`npl_record_set`; invalid rest
ranges raise an error object; `lex-string`/`lex-bar-symbol` concatenate a
reverse piece list once; `npl_read_file` detects a short read; dead
`npl_call_cc` is annotated; `runtime-hardening` (7) and the P5 reader corpus
cover these. Cross-form continuation remains a documented deviation and is
guarded by `src/repl/tests/interop.in`.

### F1: C memory core (implemented 2026-11-23)

Extend `(npl ffi)` with a small, explicit C memory model.

- Allocation: `foreign-alloc size [alignment]`, `foreign-free`,
  `foreign-copy`, `foreign-size`; no implicit finalizers, use
  `with-resource`.
- Scalar views: `pointer-ref-{u8,u16,u32,u64,i8,i16,i32,i64,float,double,
  pointer}` and setters, plus `pointer+offset`. Address arithmetic uses a
  pointer value or a non-negative byte offset, never a Scheme fixnum
  containing an address.
- Arrays: `c-array` is a view `(pointer length element-type)`;
  `make-c-array`, `c-array-ref`, `c-array-set!`, `c-array-length`,
  `c-array->vector`, `vector->c-array`. Views carry length and perform
  bounds checks. Element types are the scalar set above.
- Foreign memory holds scalars and pointers only; storing an arbitrary
  `NplVal` is not allowed, so the collector never scans C memory. A pointer
  stored in C memory does not keep an NPL object alive.
- Access goes through generated C helpers or `memcpy`-based typed access,
  not NPL byte arithmetic, so alignment and aliasing stay defined.

Verification: allocation/alignment/overflow/bounds tests; GC verification;
`with-resource` release on normal return, raise, and continuation escape.

Implementation: `runtime/ffi-memory.c` and `lib/npl/ffi.sld`; allocation is
zero-filled with a default 16-byte alignment, `pointer+offset` views carry
the remaining length and are not freeable, and typed loads/stores use
`memcpy` after bounds and alignment checks. Tests: `ffi-memory` 42 and the
`ffi-memory` nplc/npli fixture. C structs remain F2.

### F2: C structs and typed stubs (implemented core 2026-11-23)

- `(define-c-struct name "c_type" (field c-type) ...)` records
  `sizeof`/`offsetof` through a generated C probe and provides
  `make-c-struct`, `c-struct-ref`, `c-struct-set!`, `c-struct-pointer`.
- Struct views are pointer + descriptor; bounds are field names, not raw
  offsets. Only pointer-to-struct is exposed. By-value struct arguments and
  results stay out of scope; wrap those in targeted C functions.
- Extend `define-c-function` types with `pointer`, `c-array`, and
  `struct:name`. Array arguments are a pointer plus an explicit length, or a
  `c-array` view whose length is checked before the call. No callbacks.
- Add the POSIX descriptors used by SRFI 170: `stat`, `dirent`, `passwd`,
  `group`, `utsname`, `timespec`, `timeval`, `rlimit`, with platform guards
  and feature detection.

Verification: layout probes against the host C compiler; platform-guarded
struct tests; no structs with NPL references.

Implementation: `define-c-struct` compiles and runs a `sizeof`/`offsetof`
probe at expansion time and emits a quoted layout descriptor; `make-c-struct`,
`c-struct-ref`, `c-struct-set!`, and `struct:name` typed-stub arguments are
implemented. `timespec` and `tm` are the first descriptors; the remaining
POSIX catalog (`stat`, `dirent`, `passwd`, `group`, `utsname`, `timeval`,
`rlimit`) moves with P2. `define-c-struct` reads the build-time
`c-struct-layouts.meta` (R6), so imports do not run a C compiler. Tests:
`c-structs` 8 and the `structs` C extension.

### P1: SRFI 19 time (implemented 2026-11-23)

`(npl time)` / `(srfi 19)`: date/time records, conversions, formatting,
parsing, timezone support, and `current-time`/`time-utc`/`time-monotonic` via
`clock_gettime`, `localtime_r`, `gmtime_r`, `mktime`, and `strftime`.
Pin `TZ` in tests and cover DST and non-hour offsets.

Implementation: `(npl time)` uses `define-c-struct` for `timespec`/`tm` and
the core package `libnpl_time` for clock and calendar conversions.
`current-time`, `time-resolution` (nanoseconds), `time-utc->date`,
`date->time-utc`, `current-date`, `make-date`, the full `date->string`
directive set, `string->date`, Julian-day conversions, and TAI/monotonic
aliases are implemented. Tests: `srfi-19` 36 and the nplc/npli `time`
fixture.

### N1b: zlib sample (implemented 2026-11-23)

`(npl demo zlib)` is the second external package: caller-owned bytevector
buffers over `zlibVersion`, `compressBound`, `compress`, and `uncompress`.
CMake builds it only when zlib development files are present; the
`native-zlib` compiler suite and R7RS fixture are skipped otherwise.

### P2-P4: SRFI 170 POSIX (implemented 2026-11-23)

`(npl unix)` / `(srfi 170)` is the core `libnpl_unix` package. The full
surface is implemented in one package split:

1. Files, directories, links, metadata, and `stat`.
2. Environment, users/groups, process IDs, time, temporary files.
3. Terminal, file descriptors/ports, and optional operations.

Return Scheme records, vectors, lists, and strings; do not expose raw
`struct` pointers. Keep targeted C wrappers where a generic struct would be
unsafe. Platform-specific facilities are present only when the host has
them, and `cond-expand`/feature checks report that.

### N3: static/shared link modes (implemented 2026-11-24)

Artifact form is orthogonal to package tier and consumption mode. Both
`libnpl_<name>.a` and the shared object are built for core and external
native packages; `nplc` defaults to static linking and has `--native=shared`;
`npli` is the dynamic runtime and never invokes a C compiler at import time.
`native.meta`, `native-package` declarations, relocatable rpaths, and the
size/dependency checks are in [link-modes](../design/link-modes.md) and
`(tools link-modes)`.

### T1: threaded runtime foundation

Design: `.agents/design/threads.md`. Start with a 1:1 pthread substrate
behind an NPL scheduler interface; M:N/green threads are a later scheduler,
not part of SRFI 18. Before any SRFI 18 surface:

- Per-thread roots, stack ranges, and trampoline/dynamic state.
- Stop-the-world coordination with published stack/register snapshots,
  per-thread roots, and process roots; thread-safe allocation, write
  barriers, and remembered sets.
- Per-thread parameter/exception-handler stacks and dynamic-wind state.
- Audit all mutable runtime globals, including trampoline/unwind state,
  stack limits, and reader recovery; classify each as thread-local,
  process-wide immutable, or synchronized.
- Mutex/condition-variable primitives over pthreads.

Safepoint and lock-order rules are specified in
[`design/threads.md`](../design/threads.md). Before SRFI 18, validate that a
parked mutator's roots/registers remain visible during collection, that
collectors cannot deadlock while requesting a world stop, and that a hot
generated loop observes cancellation. Stress collection while other threads
allocate and while safe wrapped calls are parked; unwrapped C calls must keep
GC excluded. Exercise concurrent operations on a shared directory handle and
FFI block under the chosen ownership/locking contract, including close/free
races. Verify parameter inheritance/default-binding isolation and shared
runtime TLS identity using the target/link-mode rules in the design.
This is a runtime design increment with its own seed relay.

### T2: SRFI 18 threads

`(npl thread)` / `(srfi 18)` over T1: threads, mutexes, condition variables,
thread-local storage, `thread-yield!`, joins, and termination. Verify
single-thread behavior first, then stress GC, allocation, and blocking.
Include cross-thread user continuation invocation, termination completion
before return, abandoned mutexes, and join exception outcomes per SRFI 18.

### T2b: virtual threads (JVM-style, after T2)

After T2, add a private CPS root for the scheduler and define public
`call/cc` behavior across that boundary before exposing a separate
`(npl thread virtual)` API. The scheduler continuation is one-shot; the
one-shot wrapper alone does not establish the required boundary. Then
add an M-carrier/N-virtual-thread run queue and yielding blocking operations
that never suspend across a live C frame. See
[`design/threads.md`](../design/threads.md).

### T3: SRFI 230 atomic

`(npl atomic)` / `(srfi 230)` over runtime atomic flags, boxes, fixnum boxes,
and pairs; compare-and-swap operations, GC barriers for arbitrary-value
payloads, and memory-order documentation. Atomic vectors are not in SRFI 230.

### T4: full SRFI 226

After T1-T3, implement prompts, continuation marks, fluids, and the thread
libraries. Do not claim SRFI 226 conformance before then.

### Optional: `sort` / SRFI 132 (implemented in 0.1.2)

`(npl sort)` and `(srfi 132)` are present, with the SRFI 95 names; no
remaining work in this plan.

### F1 API sketch

```scheme
;; Allocation.  SIZE is bytes; ALIGNMENT is a power of two.
(foreign-alloc size [alignment])          ; -> pointer
(foreign-free pointer)                    ; -> unspecified
(foreign-size pointer)                    ; -> known byte size
(foreign-copy pointer size [alignment])   ; -> pointer

;; Address arithmetic; never stores an address in a fixnum.
(pointer+ pointer offset)                 ; -> pointer
(pointer-offset pointer)                  ; -> non-negative exact integer

;; Scalar access.  TYPE is one of
;; u8 u16 u32 u64 i8 i16 i32 i64 float double pointer.
(pointer-ref pointer type [offset])
(pointer-set! pointer type value [offset])

;; Array views.  The view owns no memory.
(c-array pointer length type)             ; -> c-array
(c-array? value)
(c-array-length array)
(c-array-ref array index)
(c-array-set! array index value)
(c-array->vector array)
(vector->c-array vector type [pointer])
```

Rules:

- A `c-array` holds `(pointer length type)`. `c-array-ref`/`set!` check the
  index and the scalar type; `pointer-ref`/`set!` are the unchecked raw form
  and require an explicit offset.
- `foreign-alloc` zero-fills by default; this is tested and documented.
- `foreign-free` does not invalidate views; a view over freed memory is
  undefined, as in C. `with-resource` remains the recommended pattern.
- Scalars are converted by generated C helpers in `runtime/ffi.c`; no NPL
  byte arithmetic and no type punning through `NplVal`.
- `pointer` elements store a C address inside foreign memory. The collector
  does not follow it and it does not root an NPL object.
- The API is available from `(npl ffi)` and is used by `(npl unix)` later.

### F1 tasks

1. Runtime helpers for aligned allocation, size tracking, and typed
   load/store, including overflow and alignment checks.
2. `(npl ffi)` views and constructors; documentation in `docs/ffi.md`.
3. Compiler/evaluator tests for both paths.
4. GC verification: a pointer in foreign memory does not keep an NPL object
   alive; `with-resource` frees on raise and continuation escape.
5. Alignment and byte-length tests on macOS and Linux.

Exit criteria: no POSIX dependency; all tests pass on both `nplc` and
`npli`; no `NplVal` can be stored in foreign memory.

## F2 API sketch

```scheme
(define-c-struct stat "struct stat"
  (st-dev unsigned-long)
  (st-ino unsigned-long)
  (st-mode unsigned-int)
  ...)

(make-c-struct stat)                     ; -> zeroed storage
(c-struct-ref pointer stat 'st-mode)
(c-struct-set! pointer stat 'st-mode value)
(c-struct-pointer pointer stat 'st-size) ; -> pointer to a field
```

`define-c-struct` records `sizeof`, `_Alignof`, and field offsets from a
generated C probe. Field types use the F1 scalar set; nested structs and
arrays are added only if the POSIX descriptors need them. By-value struct
parameters and results are out of scope.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Foreign memory lifetime bugs | `with-resource`, no-finalizer rule, ASan/valgrind on C helper tests. |
| Struct layout drift across platforms | Host-generated `sizeof`/`offsetof`; no hardcoded offsets in NPL. |
| `NplVal` stored in C memory | Scalar whitelist; no `any` element type; review gate. |
| Thread GC races | T1 design note and stop-the-world tests before SRFI 18. |
| Socket portability | POSIX feature probes; optional operations raise a documented error. |
| Blocking FFI call stalls threads | Document synchronous foreign calls; add a blocking boundary after T1. |

## Verification

- Every increment: `tools/check_full_compiler.sh`, the full
  `tools/run_tests.sh` with relay, and the relevant native/npli fixture.
- FFI: allocation/free, alignment, bounds, overflow, GC verification,
  `with-resource` on escape/raise.
- Time: fixed `TZ`, UTC/local, DST, formatting/parsing round trips.
- POSIX: platform guards, missing-operation errors, file-system cleanup.

- F1/F2: C helper unit tests, host layout probes, and `nplc`/`npli` differential tests.

## Open decisions

- Native packages: `.agents/design/native-packages.md` is the accepted
  direction: core packages are linked by the toolchain (A), external
  packages are loaded through the FFI (B), with one NplVal ABI and one
  binding manifest. The first migration is `(npl time)`. Implementation is
  not part of the current commit.

- Whether `define-c-struct` should generate per-field accessors or only a
  descriptor plus generic `c-struct-ref`. Start with the descriptor; add
  accessors only if POSIX code needs them.
- Whether `c-array` element `pointer` is enough for POSIX `char **` cases or
  whether a dedicated `string-array` helper is needed after the first POSIX
  PR.
- Thread stack size and stop-the-world handshake are decided in the T1
  design note, not here.
