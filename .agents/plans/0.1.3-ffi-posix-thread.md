# 0.1.3 FFI, POSIX, Time, and Threads

Status: accepted direction, 2026-11-13, after merging 0.1.2 (PR #3) and
reviewing `.agents/reviews/2026-11-12-features-and-roadmap.md` with the
Appendix review opinions. This plan supersedes the 0.1.3 sketch in
[0.1.2-srfi](0.1.2-srfi.md) and keeps the 0.1.x release line.

Scope:

- FFI memory: C arrays, scalar views, and C structs.
- `(npl time)` / `(srfi 19)`.
- `(npl unix)` / `(srfi 170)` (full POSIX surface, split across PRs).
- `(npl thread)` / `(srfi 18)` and `(npl atomic)` / `(srfi 230)`.
- Full SRFI 226 after threads.
- The accepted review findings from the Appendix review as a hardening
  increment before the runtime work.

## Review intake

The Appendix review accepted, rejected, or qualified the original roadmap.
This plan follows its recommendations rather than the original priority list.

### Accepted hardening work

| Item | Action |
|---|---|
| F3 record accessor bounds | Validate `1 <= index < record length` in `npl_record_ref`/`npl_record_set`; add a negative test through the internal primitive. |
| F4 rest-arity exit | `npl_rest_arguments` must raise an error object, not print and `exit(1)`; add a differential `guard` test for nplc and npli. |
| F5 lexer O(n²) | Accumulate `lex-string` pieces in a list and call `list->string` once. |
| F6 `npl_read_file` | Distinguish a short read from an error and raise a file error. |
| Cross-form continuation | Document the npli/`load` vs nplc difference in `docs/r7rs-conformance.md` Known deviations and add a single-form reentry fixture. |
| Dead `npl_call_cc` | Remove it or annotate why it is retained; the seed does not generate it. |
| Reader fuzzing | Add a small reproducible corpus/property test for untrusted datum input, including `#nA` ranks and cycles. |
| `sort` / SRFI 132 | Keep as an optional library increment after the runtime work. |

### Rejected or qualified

- F1/F2 (REPL continuation reentry, escape-only frames) are not defects; the
  behavior is the recorded evaluator decision D3, and the test exists in
  `src/repl/tests/interop.in`. Only the documentation gap is accepted.
- F7 is not a live overflow; the pointer representation is a design
  cleanliness item for the FFI memory work.
- The roadmap's library version selectors, `syntax-case` trigger conditions,
  and "fix F1 before threads" entries conflict with R7RS or recorded
  decisions; they are not adopted.
- A capability sandbox around `(npl internal primitive)` is not a 0.1.3
  deliverable; restricting internal imports needs a separate capability
  design.

## Increments

### H1: runtime and reader hardening

Implement the accepted items above. No new library API.

Verification: existing gate plus differential rest-arity, record-bounds,
reader-fuzz, and single-form reentry fixtures; `check_gc.sh` for runtime
changes; seed relay for the lexer change.

### F1: C memory core

Extend `(npl ffi)` with a small, explicit C memory model.

- Allocation: `foreign-alloc size [alignment]`, `foreign-free`,
  `foreign-copy`, `foreign-size`; no implicit finalizers, use
  `with-resource`.
- Scalar views: `pointer-ref-{u8,u16,u32,u64,i8,i16,i32,i64,float,double,
  pointer}` and setters, plus `pointer+offset`. Address arithmetic uses a
  pointer value or a non-negative byte offset, never a Scheme fixnum
  containing an address.
- Arrays: `c-array` is a view `(pointer length element-type)`;
  `make-c-array`, `c-array-ref`, `c-array-set!`, `c-array-length`,
  `c-array->vector`, `vector->c-array`. Views carry length and perform
  bounds checks. Element types are the scalar set above.
- Foreign memory holds scalars and pointers only; storing an arbitrary
  `NplVal` is not allowed, so the collector never scans C memory. A pointer
  stored in C memory does not keep an NPL object alive.
- Access goes through generated C helpers or `memcpy`-based typed access,
  not NPL byte arithmetic, so alignment and aliasing stay defined.

Verification: allocation/alignment/overflow/bounds tests; GC verification;
`with-resource` release on normal return, raise, and continuation escape.

### F2: C structs and typed stubs

- `(define-c-struct name "c_type" (field c-type) ...)` records
  `sizeof`/`offsetof` through a generated C probe and provides
  `make-c-struct`, `c-struct-ref`, `c-struct-set!`, `c-struct-pointer`.
- Struct views are pointer + descriptor; bounds are field names, not raw
  offsets. Only pointer-to-struct is exposed. By-value struct arguments and
  results stay out of scope; wrap those in targeted C functions.
- Extend `define-c-function` types with `pointer`, `c-array`, and
  `struct:name`. Array arguments are a pointer plus an explicit length, or a
  `c-array` view whose length is checked before the call. No callbacks.
- Add the POSIX descriptors used by SRFI 170: `stat`, `dirent`, `passwd`,
  `group`, `utsname`, `timespec`, `timeval`, `rlimit`, with platform guards
  and feature detection.

Verification: layout probes against the host C compiler; platform-guarded
struct tests; no structs with NPL references.

### P1: SRFI 19 time

`(npl time)` / `(srfi 19)`: date/time records, conversions, formatting,
parsing, timezone support, and `current-time`/`time-utc`/`time-monotonic` via
`clock_gettime`, `localtime_r`, `gmtime_r`, `mktime`, and `strftime`.
Pin `TZ` in tests and cover DST and non-hour offsets.

### P2-P4: SRFI 170 POSIX

`(npl unix)` / `(srfi 170)`, full surface in three reviewable PRs:

1. Files, directories, links, metadata, and `stat` (uses F2 structs).
2. Environment, users/groups, process IDs, resource limits.
3. Terminal, pipes, sockets/select, and optional operations guarded by
   runtime feature detection.

Return Scheme records, vectors, lists, and strings; do not expose raw
`struct` pointers. Keep targeted C wrappers where a generic struct would be
unsafe. Platform-specific facilities are present only when the host has
them, and `cond-expand`/feature checks report that.

### T1: threaded runtime foundation

Before any SRFI 18 surface:

- Per-thread roots, stack ranges, and trampoline/dynamic state.
- Stop-the-world coordination; thread-safe allocation, write barriers, and
  remembered sets.
- Per-thread parameter/exception-handler stacks and dynamic-wind state.
- Mutex/condition-variable primitives over pthreads.

This is a runtime design increment with its own design note and seed relay.

### T2: SRFI 18 threads

`(npl thread)` / `(srfi 18)` over T1: threads, mutexes, condition variables,
thread-local storage, `thread-yield!`, joins, and termination. Verify
single-thread behavior first, then stress GC, allocation, and blocking.

### T3: SRFI 230 atomic

`(npl atomic)` / `(srfi 230)` over runtime atomics for fixnums/cells;
compare-and-swap loops, atomic vectors, and memory-order documentation.

### T4: full SRFI 226

After T1-T3, implement prompts, continuation marks, fluids, and the thread
libraries. Do not claim SRFI 226 conformance before then.

### Optional: `sort` / SRFI 132

A pure library increment, independent of the FFI/runtime work.

## Dependencies

```text
H1 -> F1 -> F2 -> P2..P4
          \-> P1
F2 -> T1 -> T2 -> T3 -> T4
```

P1 can proceed in parallel with F2; POSIX `stat`/`passwd`/`group` and time
structs depend on F2.

## Verification

- Every increment: `tools/check_full_compiler.sh`, the full
  `tools/run_tests.sh` with relay, and the relevant native/npli fixture.
- FFI: allocation/free, alignment, bounds, overflow, GC verification,
  `with-resource` on escape/raise.
- Time: fixed `TZ`, UTC/local, DST, formatting/parsing round trips.
- POSIX: platform guards, missing-operation errors, file-system cleanup.
- Threads: single-thread semantic parity, then GC stress, races, blocking,
  and termination tests; `check_gc.sh`.
- Reader/record/rest-arity: negative tests that fail on the previous seed.

## Open decisions

- Whether `define-c-struct` should generate per-field accessors or only a
  descriptor plus generic `c-struct-ref`. Start with the descriptor; add
  accessors only if POSIX code needs them.
- Whether `c-array` element `pointer` is enough for POSIX `char **` cases or
  whether a dedicated `string-array` helper is needed after the first POSIX
  PR.
- Thread stack size and stop-the-world handshake are decided in the T1
  design note, not here.
